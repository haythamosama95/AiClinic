## 1. Missing `calendar.ts` before the T001 harness

**Question:** P3.4 prerequisites list merged P3.3 (`grant`, DO schema, `coverage_mirror`, etc.). Code imports `addDuration` / `DurationScale` from `ai-platform/src/coverage/calendar.ts`, but that file is absent (empty `src/coverage/` directory; never in git history). P3.3 `tasks.md` marks T015 `[X]` for that file. Should `calendar.ts` be restored from P3.3 spec FR-010 before H-AP can run, or was it intentionally omitted from this branch?

**Assumption:** Restore `ai-platform/src/coverage/calendar.ts` from P3.3 FR-010 before the T001 H-AP command. It was not intentionally omitted. P3.3 owns it (plan Files, Sequencing steps 15 and 29, tasks T015 and T029). Those task marks stay `[X]`. The empty directory is a tree gap: the file has no git history, and `src/vendor/entrypoint.ts` and `src/quota-do/coverage.ts` already import it. The restored module exports `DurationScale` as the string `"staging"` and `addDuration(startIso, unit, count, scale?)`. `unit` is `"month"` or `"day"`. An omitted `scale` adds `count` months in UTC, keeping the start's day-of-month and time and clamping that day to the last day of the target month, and adds `count` days as exact multiples of 24 hours. `scale` `"staging"` keeps that unscaled `count` and replaces the unit length: one month is 30 minutes and one day is 1 minute. It does not compress a previously computed calendar interval. The return value is `Date.prototype.toISOString()`. `2026-01-31T10:00:00.000Z` plus one month is `2026-02-28T10:00:00.000Z`. `2024-01-31T10:00:00.000Z` plus one month is `2024-02-29T10:00:00.000Z`. `2026-03-01T12:00:00.000Z` plus one month at `"staging"` is `2026-03-01T12:30:00.000Z`. The resumed P3.4 T001 run writes that file once, then adds the failing test. That write is the missing consumed module. It does not change callers. P3.4 plan sentences that say the file stays as P3.3 left it, and that this unit adds no new source file, apply after this restoration: later P3.4 tasks do not edit it and do not add any other source file. Stop conditions 2 and 5 do not fire again for this absence. The T001 command then loads the worker and fails because `coverClinic` is missing and `POST /v1/requests` is not charged to a term.

**Why:** FR-010, 03 §6.1, and E2E-P3.3-09 already fix month clamping, day multiples of 24 hours, and the staging map of one month to 30 minutes and one day to 1 minute. The live imports name `addDuration` and `DurationScale`, and `durationScaleFromEnv` passes only `"staging"` or omits the scale. There is no commit to restore. Leaving the import broken makes the T001 harness fail on module load instead of on the missing `coverClinic` and term charging.

### F-10-1 — `usage_event.period` weakened to a shape regex to hide a setup deviation

- **Scenario:** S10-001 (and, via shared helpers, S10-020…S10-033 in the prose-guard file)
- **Test:** `ai-platform/test/e2e/stage-10-route-retry-idempotency.test.ts:440` (inside S10-001, :397); helpers `assertValidationFailedSettlement` / `assertCompletedSettlement` in `ai-platform/test/e2e/stage-10-prose-guard-stream.test.ts:430,448` (regex at :444,:457)

- **Actual test assertion:** `expect(usage[0]?.period).toMatch(/^\d{4}-\d{2}$/)` — a shape-only regex. The stage-10 tests provision with the harness `DEFAULT_ENTITLE_PAYLOAD` (`period_start: "2026-01-01T00:00:00.000Z"`, `ai-platform/test/e2e/harness/control.ts:216-222`), so the real value is `2026-01`; the regex obscures both the setup deviation and the value.
- **VERDICT:** WEAK TEST
- **SEVERITY:** LOW
- **Evidence:** catalog `docs/testing/catalog/stage-10-accept-route-invoke-stream.md` (S10-001, Setup FRESH); `ai-platform/test/e2e/harness/control.ts:216-218`; contrast `ai-platform/test/e2e/stage-11-completed-failed-cancelled.test.ts:73-81,701,889` (stage 11 uses `JULY_ENTITLE` and asserts `period === "2026-07"` exactly). Documented only as an "alignment" in `ai-platform/test/e2e/reports/stage-10.md` §5.5 — never filed as a conflict.
- **FIX BRIEF:** Entitle stage-10 scenarios with `period_start: 2026-07-01T00:00:00.000Z` / `period_end: 2027-01-01T00:00:00.000Z` (matching the catalog's Setup FRESH and stage 11's `JULY_ENTITLE`) and assert `usage[0]?.period === "2026-07"` in the shared settlement helpers. ### F-12-1 — S12-050's "live race" is structurally unwinnable; the `[SEED]` fallback does all the work

- **Scenario:** S12-050 (support lookup of an in-flight request → empty attempts, null envelope)
- **Test:** `ai-platform/test/e2e/stage-12-support-lookup.test.ts:550-605`
- **Catalog expectation:** Setup references S12-009's in-flight row arrangement; S12-009's `[SEED]` justification is "justified only as a determinism fallback; prefer the live race."
- **Actual test assertion:** The test POSTs with the **default** `FakeAdapter` (no hang spy installed — :556-565), reads `accepted`, then looks up. The default fake settles in milliseconds, so the live lookup almost always returns a terminal body, `isCatalogInFlight(body)` fails, and the test falls back to `seedInvokingRow` (:585-593) — the in-file comment admits "Live race lost: fake adapter often settles before lookup." Contrast S12-009 (`stage-12-get-lookup.test.ts:667-686`), which installs a `HangFake` (8 s hang) precisely to make the window winnable. S12-050 therefore effectively always runs on the seed while appearing to exercise the live path.
- **VERDICT:** WEAK TEST (effectively unjustified `[SEED]` — the catalog's fallback justification is conditioned on a genuine live-race attempt)
- **SEVERITY:** LOW (the seeded row does exercise the lookup code path and the assertion set is correct; but the scenario's primary arrangement is never executed)
- **Evidence:** catalog `docs/testing/catalog/stage-12-lookup-and-support.md` S12-050 + S12-009 seed justification; `ai-platform/test/e2e/stage-12-support-lookup.test.ts:556-593`; contrast `ai-platform/test/e2e/stage-12-get-lookup.test.ts:667-686`.
- **FIX BRIEF:** Install the same `HangFake` spy S12-009 uses (spy `FakeAdapter` with `hangUntilAbort(signal, …)`) before the POST so the live lookup genuinely races an in-flight request; keep `seedInvokingRow` as the documented determinism fallback only.

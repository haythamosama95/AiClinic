## Findings implemented

  No fix step was deferred.

## Changed files and symbols

New migration (only one): `backend/supabase/migrations/20261023100000_fv_m1_membership_last_administrator_guard.sql`

- New `auth_internal.assert_not_last_administrator(uuid, uuid)`: `SECURITY DEFINER`, `search_path = ''`, EXECUTE
  revoked from PUBLIC/anon/authenticated (the one-argument form has no explicit grants; the schema default
  privileges already withhold `authenticated`). Returns when the target is not an administrator member of the
  org. Otherwise locks the org's administrator memberships (`FOR UPDATE`, ordered by `user_id`), counts other
  administrator memberships whose staff row is active and not deleted, and raises `LAST_ADMINISTRATOR`
  (`P0002`) below 1.
- `auth_internal.assert_not_last_administrator(uuid)`: same signature and ACLs; now calls the two-argument form
  for every org (ordered by id) where the target holds an administrator membership. The `LIMIT 1` branch
  organization pick is gone. `set_staff_active` and `delete_staff_member` call this form unchanged.
- `auth_internal.update_staff_member`: redefined from `20261014170400` with one change: the guard gate uses the
  locked current-org membership role (`v_locked_membership_role`), and calls the two-argument form with the
  current org.
- Callers reviewed: `20260611170000` (`update_staff_member`, `set_staff_active`), `20260613210000` and
  `20260614100000` (`delete_staff_member`), `20261014170400`. Only `update_staff_member` gated on the global
  role, so only it was redefined.

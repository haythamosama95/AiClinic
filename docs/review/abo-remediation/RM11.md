# RM11 — Desktop checkout flow

## Findings and implementation

- **R3-C1:** Made offers, billing-contact and checkout screens work in an outer scroll view at short and tall viewport sizes. Contact and checkout layouts no longer use a fixed `Spacer` that can overflow. Added widget coverage for both 360×480 and 1200×1000 layouts.
- **R3-M4:** Offer selection now clears terms acceptance when offer/version/terms identity changes. When checkout reports an unavailable offer, the parent returns to fresh offer selection; checkout no longer substitutes an undisplayed price or version. Reopening the offers screen resets its state.
- **R3-M6:** Added `BillingMoney.format` for localized display of EGP minor units as two-decimal major units and used it in offer cards and checkout. Integer wire and storage values remain unchanged.
- **R3-M1:** Added local billing-token request-use reservations, rotating before the local 60-use ceiling, and invalidating/retrying GETs after a server exhausted-token response.
- **R3-C2 step 2 (Dart):** `AboClient` maps `idempotency_conflict` to a typed clinic exception. Checkout reads for the same ID are single-flighted.

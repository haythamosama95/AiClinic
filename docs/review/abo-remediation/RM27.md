# RM27 — Deletion and held status

Implemented R6-PT3 (durable deletion and purge) followed by R7-PS1 (held-binding unavailable projection).

## Changes

- `ai-platform/src/coverage/transfer.ts`: `acceptDeleteInstallation`, `resumeDeleteInstallation`, `dispatchDeletionCommands`, and fail-closed coverage inspection. Deletion acceptance pins org, installation and epoch with actor, reason, signer and accepted command; freeze acknowledgement gates held/retired state; open term and reservation identities survive purge; accepted work resumes from the five-minute dispatcher. Held retirement requires authoritative empty term and reservation inventory.
- `ai-platform/src/quota-do/coverage.ts`: `setTransferPendingRPC` serializes the deletion fence, snapshot event and sequence increment. Held open coverage projects as `transfer_pending` while preserving term and suspension metadata. A completed deletion fence can be adopted by RM26 transfer only for the exact pinned source installation and epoch.
- `ai-platform/src/vendor/entrypoint.ts` and `ai-platform/src/worker.ts`: authenticated deletion replay, durable completion, cron dispatch and Durable Object state wiring.
- `ai-platform/src/retention/index.ts`: stable purge audit identity and idempotent audit insertion.
- `ai-platform/migrations/20261020150000_rm27_durable_deletion.sql` and `ai-platform/schema.snap.sql`: durable deletion command and indexes. The migration is installed by system, E2E, ABO cross-worker, admission-credit, request-orchestrator and load harnesses; relevant reset/table lists include the new table.

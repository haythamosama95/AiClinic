## Findings implemented

- **R4-A1 (P1):** Added an ordered append-only `grant_outcome_event` log and one-row `grant_outcome` compatibility view. Migration 0014 preserves the old table as `grant_outcome_legacy`, backfills each legacy result without rewriting its fact log or work state, marks old success as terminal, and retains old rejection/conflict as nonterminal history. Paid results now append by lease token; the event insertion, conditional fact row, and work transition share a batch fenced by the exact open work row and lease token. A terminal receipt prevents extra apply attempts; a voided response is terminal without value. Rebuild maps old facts idempotently into legacy attempt events, replays new events by attempt ID, and only treats a terminal event as completed for paid retry gating. Existing read consumers continue using the compatibility view.
- **R4-A2 (P2):** The complimentary relay checks URL tenant, deterministic action grant ID, and source kind/ref before platform dispatch. It stores the canonical request and fact before dispatch and checks exact request identity on retry. A shared production receipt validator is used by paid and complimentary paths; it checks receipt schema, configured-key signature, request grant/org/hash, request contract version, applied receipt result, nonempty term IDs, and positive ledger sequence. Only a validated original receipt creates a terminal outcome. Invalid/missing/mismatched receipts raise AL-07 and leave the accepted command at platform-succeeded for recovery. The relay preserves platform's durable-claim route decision and does not bind a receipt to a possibly newer live installation.

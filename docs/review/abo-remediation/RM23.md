# RM23 — Lifecycle placement and catch-up

Status: **complete**, 2026-10-20. Complete CI passed on validated commit
`74301b5f9eec2420cd26fa03fd9bf22f71647a46`.

## Findings implemented

- **R4-D3:** New grant placement and adjustment eligibility use a pure due-boundary plan in the same
  serialized mutation. Boundary term/hot changes and their ordered snapshots commit atomically with the
  grant. Existing identical grant replay remains before new boundary planning.
- **R4-D2:** Complimentary placement renews a live grace term from its original end, using the original
  term's settled usage snapshot; queueing and no-coverage placement use caught-up state. An authenticated
  recovery action now repairs only the oldest evidenced complimentary orphan at trusted request time.
- **R6-DM4:** Held-term release catches up lifecycle state first. Releasing during live grace ends the grace
  term as renewed, freezes settled usage, and activates the released term from the prior end; normal active
  release remains queued and no-coverage release activates only when no unheld predecessor exists.

The explicit recovery-action contract supplied for this run is implemented through the ABO
`POST /ops/coverage/recover-stranded` route, VendorEntrypoint HP assertion method, and pinned tenant DO
RPC. The DO verifies retained grant/evidence rows, rejects ambiguous or previously activated/used terms,
and commits term state, ordered coverage events, permanent action/term markers and a durable audit outbox
fact atomically. Vendor retries return the immutable result; D1 retains the recovery fact and request hash
so a replay remains exact after DO rebuild.

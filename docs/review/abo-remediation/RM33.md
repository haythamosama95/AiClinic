# RM33 — Routing configuration integrity

Status: complete. Validated by complete CI run [39716022509](https://github.com/haythamosama95/AiClinic/actions/runs/39716022509) on `bd2ec3430ba52e0b7c67c8e61de37e5e34ce9b12` (18 of 18 jobs succeeded). No new `it.skip` was added in the RM33 diff. The RM32 owner-waived skips are unchanged.

## Findings implemented

- **R8-ROUTE1 (P1), steps 1–3:** a shared pure parser (`ai-platform/src/router/policy-document.ts`, `parseRoutingPolicyDocument`) is used before publish writes, before canary/promote state changes, and at runtime through `validatePolicyDocument`. Identity-only, unsupported-schema and missing-catch-all documents are rejected at publish with `invalid_policy_document` (HTTP 422) and write nothing.
- **R8-PUB1 (P1), routing half only:** content is stored under a digest-keyed R2 key `control/routing-policy/<id>/<version>/sha256-<digest>.json`. `routing_policy.content_sha256` is written in the same D1 batch as the row and audit. A losing publication cannot replace winner content. `loadRoutingPolicyDocument` fails explicitly on digest mismatch. The terms half is RM34 and was not touched.
- **R8-ROLLBACK1 (P2):** a new `routing_policy_activation` table holds `generation`, `active_version`, `predecessor_version` and `predecessor_state` (`unknown` / `none` / `known`). Promote and rollback each run in one D1 batch with a generation-guarded update. The audit insert is conditional on the update (`changes() > 0`), so a stale transition commits nothing. Rollback restores only a `known` predecessor. `unknown` returns 409 `rollback_predecessor_unknown`, and `none` returns 409. Rollback never follows publication order.

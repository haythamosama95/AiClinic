# RM30 — Usage identity across recovery

Status: complete. Validated by complete CI run 39679626741 on `a5bf6d4ef`. Local tests, builds, linters, and type checks were not run, per the phase constraint.

## Findings implemented

- **R9-PUS1:** Durable Object settlements now allocate a monotonically increasing per-installation `accounting_seq` in the same transaction as the receipt and counter change. Settlement replies and usage-adjustment outbox records carry that sequence. Coverage snapshots include the committed watermark. D1 usage rows retain `origin_request_id` and sequence, with unique identity indexes. Recovery applies only sequences beyond the latest applicable snapshot watermark, once, on the recorded term; it blocks gaps, corrupt/missing watermarks, and historical rows without provable identity instead of using timestamps.
- **R9-PRET1:** Request identity survives independently of the erasable `request_id` FK. Journal writes enrich an existing accounting fact with provider usage details. Retention checkpoints term state from the latest authoritative coverage snapshot and purges aged usage only when the term is proven ended. Held, queued, active, grace, and unknown terms remain retained.
- The required independent review at `d0ca7d55c0160afca4cb69b58084542f3669cba1` identified three implementation gaps; all are now addressed: replay persists the highest sequence even for zero-weight rows; normal/fallback settlement commits enqueue the usage fact with the receipt and counter update, while recovery refuses an occupied DO with an unresolved intent; and retention leaves pending settlement requests, attempts, and envelopes intact.
- No recipe step was intentionally deferred. Complete CI confirmation remains pending.

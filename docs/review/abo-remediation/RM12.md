# RM12 — ABO accepted operator commands and erasure fencing

## Implementation record

- R6-O1: added a challenge-keyed accepted-command store. Local release, manual chargeback, and erase acceptance atomically store the operation, actor, target, contract version, action row/fact, and consumed assertion. Retries use current Access and resume before freshness/replay checks. Local mutation batches use a lease token; release rechecks full reversal in the release/work batch. Begin-transfer intent is stored before platform dispatch; retries reuse the stored operation and assertion, and action audit plus transfer runner work are written with the saved result in one batch.
- R8-CONSOLE3: relays reserve action IDs against actor, method, subject, contract version, and canonical arguments before dispatch. Changed arguments conflict before invocation. Completed relays return their stored platform result.
- R6-O2: added per-org erasure generations, billing-contact generation binding, a raw-evidence registry, and a bounded cleanup outbox. Existing notification and inquiry keys are backfilled. Callback and inquiry uploads claim the checkout contact generation before R2 writes and finalize against the current fence. Erasure advances the fence and schedules current and in-flight registered objects for deletion. A callback for an erased checkout retains its hash and normalized processing path without restoring the raw body. Housekeeping retries failed deletes.
- Seam for RM16: transfer fast-path receipt linkage and reconstruction from the original signed package remains with RM16; this phase does not implement R4-A2.

Implementation files and primary symbols: `abo/migrations/0012_accepted_commands_erasure_fence.sql` and `abo/migrations/0013_notification_provider_txn_id.sql`; `abo/src/ops/index.ts` accepted-command reservation/commit and relay paths; `abo/src/clinic-api/billing-contact.ts` contact-generation binding; `abo/src/evidence/raw.ts` raw-evidence claim/finalize/cleanup; `abo/src/notify/intake.ts` callback and inquiry intake; `abo/src/work/runner.ts` normalized callback transaction loading; and `abo/src/housekeeping/run.ts` cleanup retry scheduling. Migration order is `0012`, then `0013`.

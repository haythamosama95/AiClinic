## Implementation record

- Decision 1, launch-state reads: the four formerly unreadable conditions (`channels_version`, `key_self_check_passes`, `platform_signing_key_set`, `manual_entitle_path`) are now read as described in the decisions.
- Decision 2, thresholds: `MAX_AGE` 5 minutes and `OVERLAP` 15 minutes.
- Decision 3, unmapped audit actions raise AL-21 `unclassified`.
- Decision 4, backend binding: the DB URL must name the target Supabase project ref, either host `db.<ref>.supabase.co` or user `postgres.<ref>`.
  - Reason: every Supabase database is named `postgres`, so the database name cannot identify the project.
- Decision 5, term count: sums live term rows across every installation, including deleted ones. Requires a clean production platform. The D1 mirror is dropped.
  - Reason: the count is taken from the live source, so a mirror cannot drift from it.
- Decision 6, monitor host: pinned in the target descriptor.
  - Reason: the monitor destination is a fixed, reviewed value rather than runtime input.
- Decision 7, `launch_check_reader` is read by `psql`.
  - Reason: the reader is a single read-only database path.
- Decision 8, K-11 is a separate read-only Cloudflare token with TTL 24 hours or less.
  - Reason: the launch check needs read scopes only, and a short TTL limits exposure.

## Discovered issues and known limitations

- Service keys are count-only in the live check. The issuer pin is compared on the ABO side.
- The psql connection string is passed on argv, so it is visible in the process list. This is a known risk and is not fixed.
- A stale audit-watcher lockfile refuses runs with an operator instruction.
- `ensureCoverageDoTables` may create empty tables on the first read of a deleted installation's DO. The tables hold no domain rows.
- The ABO heartbeat falls back to `HEARTBEAT_URL` until all three per-stream URLs are set.
- `e2e/fullstack/staging/p8-1-01.checklist.md` still names `HEARTBEAT_URL` as the monitor URL. Update it when the per-stream URLs are in place.
- The `offer_event` same-instant collision noted in RM34 is unrelated to RM35 and remains open there.

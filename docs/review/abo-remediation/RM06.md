# RM06 — Non-development receipt signing key

## Findings implemented

- **R9-RT3 (P1):** Removed the checked-in `PLATFORM_SIGNING_KEY` from staging and production while retaining the development fixture with an explicit local-only comment. Centralized the platform key loader in `ai-platform/src/quota-do/coverage.ts` and reused it for the direct vendor tombstone receipt path. The loader fails closed for missing or unusable material and, outside development, rejects both the published PKCS8 bytes and any private key that proves possession of the published public key, independent of `kid` or key re-encoding. The Durable Object injects its configured environment into signing requests, so the receipt and transfer paths use the same validator before signing.
- No recipe implementation step was deferred. Deployment key provisioning and rotation remain operational actions listed below, as the recipe requires.

## Changed files and symbols

- `ai-platform/wrangler.toml`: retained only the development key value.
- `ai-platform/src/quota-do/coverage.ts`: `loadPlatformSigningKey`; coverage grant, void, held-release and transfer signing request types and RPC callers.
- `ai-platform/src/worker.ts`: `GatewayObject.fetch` overwrites the signing request environment with its runtime environment.
- `ai-platform/src/vendor/entrypoint.ts`: `VendorEnv`, `callCoverageDo`, and direct tombstone receipt signing now use the shared validator.
- `ai-platform/test/platform-signing-key.test.ts`: R9-RT3 config, rejection, fail-closed and valid-key signing checks.
- No migrations.

## Tests added or changed, by finding

- `R1-SQL-04`: a global staff administrator with membership doctor in B cannot edit B's role
  permissions (single, bulk, stale claim — B matrix unchanged) nor invoke B administrator-only
  provisioning (`create_staff_account`, `admin_reset_staff_password`, `set_staff_active`); a member
  administrator in B stays authorized regardless of the global compatibility role; a member
  administrator in A keeps authority in A and B stays unchanged; the bootstrap flag does not bypass an
  existing organization's membership role; a session claiming an organization without membership
  (NULL membership role) denies every authority check and org-scoped reader;
  `staff_can_access_branch`'s administrator fallback follows the membership role (not the JWT/global
  staff role), while the assigned-branch path is preserved.
- `R1-SQL-05`: org A's denial wins over org B's grant for the same role, per reader (appointments,
  invoices/payments, services, shifts incl. `is_read_only`, billing settings, insurance listing,
  duplicate check, patient safety context, visit read, service catalog reads); A's exact grant
  permits the corresponding read with no B records returned (providers, invoices, payments, services,
  `list_services` total); the global staff role cannot substitute for A's membership role (staff
  administrator with doctor membership in A: zero rows, `FORBIDDEN`); deactivated staff denies every
  org-scoped permission reader.

## Discovered issues

- Pre-existing latent test flake (not an RM02 regression, fixed mechanically in commit `46d03654`):
  `appointment_management_crud.sql` line 616 creates a patient-1/c_doctor appointment at
  `date_trunc('hour', now() + interval '18 days')`, which collides with the regression-#2 fixture's
  fixed day-18 10:00 c_doctor slot whenever CI runs at 10:xx UTC (round 1 dispatched 10:11Z). The
  overlapping create then fails `SCHEDULE_CONFLICT`, the same-day check finds nothing and the
  reschedule succeeds. Fixed by moving the regression-#2 pair to days 24/25 (disjoint from every other
  slot in the suite); no production code was involved.
- `create_staff_rpc.sql` and `admin_reset_staff_password.sql` encoded the R1-SQL-04 defective
  behavior (bootstrap flag / global staff role authorizing provisioning after the organization
  exists); both were updated to the recipe-specified behavior with the finding named (see above).
- Naming hazard discovered while tracing fixtures: `auth_internal.delete_clinic_test_fixtures(
  p_preserve_staff_ids uuid[])` **preserves** the listed staff ids and deletes every other staff row
  plus all organizations/branches — the parameter name in several call sites reads like a delete list.
  Worth renaming or documenting in a later docs-only phase.
- The RM00 baseline flake `E2E-P3.9-01 FM-06 DO failure admits via fallback and */5 charges once`
  (`ai-platform/workers`) failed in the validating run after passing in round 1 on identical
  ai-platform code; unchanged known baseline failure per §2.9.

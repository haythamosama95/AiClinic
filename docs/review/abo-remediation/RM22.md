# RM22 — Term-local accounting

## Findings and recipe steps

- **R5-A1 (P1):** Added `reservedForTerm` over the existing reservation JSON and used it for admission allowance, grace, exhaustion, and coverage snapshot bands. The global reserved counter remains the clinic concurrency cache. Reservations retain their original `term_id` across succession. A successor therefore receives its full allowance while its predecessor's requests remain in flight.
- **R5-A2 (P1):** All term close values now use settled usage only. Calendar expiry, grace expiry/exhaustion, paid renewal, admission exhaustion, reversal, void, and transfer-out write the current term's settled `used` to `used_final`; outstanding reservations remain attached to their original term. Consumed and stale reservations arriving after a term ends add weight to that term's `used_final`. Cancellation, release, and zero-capacity settlement do not change settled counters, and release does not undo an exhaustion decision.
- **R5-A7 (P2):** Never-admitted refusals are not stored as JTI or idempotency answers, so a same-key retry reevaluates current coverage and concurrency. Legacy persisted refusal answers are filtered on load. Unchanged denials do not write the hot row; admitted answers and terminal bindings retain their existing replay behavior.

No recipe steps were deferred. The R5-A2 retained-row upgrade runs once from the Durable Object schema initializer: it subtracts still-live reservations, matched by their stored `term_id`, from existing exhausted rows. It adds a `quota_do_migration` marker and does not infer missing reservation attribution. No standalone migration file was needed.

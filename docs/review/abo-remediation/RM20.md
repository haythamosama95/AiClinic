## Seams and discovered issues

- Seam for RM26: transfer-out reservation draining and term-local accounting remain owned by RM26; this change only serializes route ownership with transfer and preserves DO replay.
- Boundary review (orchestrator adjudication): `live_value_route` contains only grant/org/installation identifiers, binding epoch, generation and route state. `reversal_command`/`grant_tombstone` retain the immutable signed request, signed DO receipt and export bytes only for idempotent replay and R2 retry; none stores an amount or term/allowance snapshot. The quota DO's term rows and durable route seal remain authoritative for applied value effects; transfer payloads are imported/exported by the DO and are not copied into D1 route rows. The `grant_void` row remains a grant-id tombstone/reference and does not supply value or entitlement state. This follows the orchestrator's boundary ruling that D1 is routing/control metadata, not canonical value/grant/entitlement authority.
- Receipt/export interpretation (orchestrator-approved): signed DO receipt and R2 export payload are retained only as opaque, integrity-checked replay bytes. D1 does not parse them into domain fields, use them to derive value/amount/term state, or make value decisions from them. Their only uses are exact terminal response replay and shipment of the already-produced export payload. This resolves the boundary seam under the explicit approval.
- Gate review: `AGENTS.md` names no executable command. `docs/setup/quality-gates.md` names the desktop foundation bundle `cd frontend && flutter pub get && flutter analyze && flutter test && flutter build windows --release`; it is unrelated to ai-platform and was not run under the no-local-validation instruction. `ai-platform/package.json` names `npm run verify-manifests` for published manifest/prompt registry tests; RM20 does not change those registries and the test gate was not run. The optional `./backend/tests/validate_local_stack.sh` is unrelated. No applicable governance-only gate command was found; the constitution supplies compliance criteria, not an executable gate. No gate was run.
- Schema snapshot has no repository code generator; the added table definitions were synchronized manually from the forward migrations. No migration or snapshot validation was run locally.
- Operator checklist for a quarantine: inspect the retained transfer row, `transfer_out` receipt/package, DO replay evidence, and current source route identity; preserve all originals. Resolve only with corroborated evidence and an approved append-only adjudication that pins the exact route identity/generation/epoch; then resume the same transfer. If evidence cannot prove those fields, keep the transfer blocked and escalate for operator decision. Do not infer identity from grant ledger, current binding, or destination state, and do not delete or rewrite the original transfer evidence.

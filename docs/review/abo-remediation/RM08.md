## 1. Findings implemented

### R3-C3 — Validate Paymob origin and use fixed API paths

- Parse the configured Paymob URL as an origin; reject credentials, paths, queries, fragments, and non-HTTPS schemes.
- Allow HTTP only for loopback when an explicit local setting or the test stub authorizes it.
- Build intention, auth, inquiry, acceptance-transaction, and hosted-checkout URLs from fixed paths and URL APIs. Invalid origins fail closed before a provider request.

### R3-C5 — Fence confirmation evidence with a lease token

- Added forward migration `abo/migrations/0010_work_lease_token.sql`, which adds and backfills a unique lease token for work rows.
- Bind every confirmation outcome batch statement to the active lease token so a replaced/stale owner cannot write payment, fact, marker, or completion evidence.
- Make successful payment evidence atomic, preserve/recover confirm work across partial legacy states, and retain authenticated redelivery recovery for marker-only notification claims.
- Keep the diagnostic bad-HMAC response at 401 when diagnostic evidence storage fails.

### R3-M5 — Bound callback body reads

- Reject declared or observed callback bodies larger than 1 MiB before decoding or intake writes, returning the empty 413 response.
- Stop accumulating chunks immediately on streamed overflow. Explicit request-stream cancellation was removed after the Wrangler-backed regression test showed that cancellation disrupted the next proxied request; runtime cleanup handles the unread body.

No recipe steps were intentionally deferred. A separate chunked-overflow follow-up through the Wrangler HTTP proxy is listed under discovered issues because the CI regression case covers the declared `Content-Length` path.

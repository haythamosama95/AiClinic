## ACL and ownership limits

PostgREST source config exposes only public/graphql_public (`backend/supabase/config.toml:12–16`); auth_internal schema has authenticated USAGE. Migration code has no explicit ALTER OWNER or FORCE RLS for these objects. Definers therefore inherit migration executor ownership; table-owner RLS bypass is assumed by implementation, but static review cannot attest deployed owners or schema CREATE/default ACLs.

Per-schema default revokes are **not proof of PUBLIC EXECUTE removal**: PostgreSQL documents that schema defaults add to global defaults and cannot revoke default global PUBLIC EXECUTE ([upstream documentation](https://www.postgresql.org/docs/current/sql-alterdefaultprivileges.html)). Existing explicit function revokes remain effective. In particular the issuer/feed/key/switch/dispatch revokes close those named surfaces; a newly created function lacking explicit revoke may still inherit PUBLIC execute. No concrete R1 API bypass was established from this fact: internal schema is not REST-exposed, and reviewed public entry points either enforce authority or lead to guarded bodies. Do not claim all inherited internal functions inaccessible solely from `ALTER DEFAULT PRIVILEGES IN SCHEMA ... REVOKE`. Source cannot prove external Supabase global defaults either way.

## T3 — P2: Arbitrary HTTP chunk boundaries can break Arabic SSE decoding

**High confidence, source defect; implementation-ready.** `frontend/lib/core/ai/https_submit_port.dart:119–126` calls `utf8.decode(chunk)` independently for each network byte chunk. HTTP does not preserve Unicode code-point boundaries: an Arabic character's bytes may span chunks. The strict decoder then throws inside the `onData` callback, outside the subscription's source `onError` forwarding at `135–139`. This loses the event bytes and can prevent a valid completed Arabic answer reaching `AiInvokeSession`/the surface, yielding a failed/dropped request despite successful platform work. P2 reflects bounded AI-display reliability; no clinical-record mutation is involved.

**Fix steps**
1. In `_HttpSseConnection`, decode the byte stream with the stateful `utf8.decoder` transformer before line splitting. Feed complete decoded lines to `_SseLineParser` using a streaming line splitter so CRLF and a code point spanning chunks are handled correctly.
2. Route decoder/parser errors into `_controller.addError` and close/cancel the connection once, using the existing guarded closure path; do not allow callback exceptions to escape unobserved. Preserve terminal-event and local-cancel semantics in `AiInvokeSession`.
3. Completion: any split inside an Arabic completed/delta payload produces the same events as unsplit UTF-8; malformed UTF-8 becomes one observed dropped-stream failure, and cancellation closes the subscription without a late event or double terminal.

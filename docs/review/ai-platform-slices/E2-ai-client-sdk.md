# Slice Review Report — E2: AI Client SDK

**Spec:** `specs/036-ai-client-sdk/spec.md` · **Branch:** `ai/036-e2-ai-client-sdk` · **Canonical:** §4.1, §5.5, §5.4

## Executive Summary

E2 delivers the artifacts its slice names: a transport-only SDK (`frontend/lib/core/ai/ai_client_sdk.dart`) behind injectable mint/submit/SSE ports (`ports.dart`), a faithful 17-code Dart mirror of the §5.4 taxonomy with the unknown→`internal_error` rule (`taxonomy.dart`), typed SSE event and terminal-state classes with no model-output reshape (`sse_events.dart`), and a 28-named-test Flutter suite (`frontend/test/unit/core/ai/ai_client_sdk_test.dart`) whose T7–T23 parameterized family genuinely covers every terminal code except the remint path. The AAT acquire-and-cache, one-shot remint, stable idempotency key, and no-auto-retry behaviour are all present and correctly structured. The substantive failures are in the stream lifecycle and the retry loop rather than in the taxonomy or caching logic. First, the cancel path is proven against a wire-impossible event: the SDK never synthesizes a cancelled outcome from its own `cancel()` — the `_cancelled` flag is set and never consulted — so against the real protocol, where §5.4 states plainly that a client-closed stream has "nobody left to receive a response," `session.terminal` completes with a bare `StateError` instead of `CancelledTerminal`; T6 passes only because both fakes inject a `CancelledEvent` into the stream on `close()`, behaviour the platform can never produce. Second, the transport-retry path is an unbounded, delay-free `while (true)` loop: a persistently unreachable platform is re-submitted in a hot loop forever, the `invoke` future never completes, and because no session exists yet the caller has no cancel handle and no timeout — the one boundary category (retry ceilings) the coverage rule names is not merely untested but absent. Third, the session both consumes `connection.events` internally for the terminal future and exposes the same stream publicly, so any single-subscription production stream breaks the moment a caller listens — a latent integration failure only the fakes' `asBroadcastStream()` conceals, and one T27 cannot catch because T27 never actually listens to the relayed events it exists to prove.

## Critical Issues

1. **The cancel terminal outcome is proven against a wire-impossible event — against the real protocol, `cancel()` yields `StateError`, not `CancelledTerminal`** (`frontend/lib/core/ai/ai_client_sdk.dart:121-127`, `:129-159`; `frontend/test/unit/core/ai/fakes.dart:148-155`, `:186-193`). §5.5 rule 5 makes closing the stream the *only* cancel mechanism, and §5.4's `cancelled` row is explicit: the 499 code "is never written to a live socket — a cancellation happens by the client closing the stream, so there is nobody left to receive a response" (`17-ai-platform.md:1723-1725`). The client-side consequence is mandatory: the SDK must synthesize the cancelled outcome locally when the caller cancels. It does not. `cancel()` sets `_cancelled = true` and closes the connection (`ai_client_sdk.dart:121-127`), but `_consumeToTerminal` never reads `_cancelled`; when the closed stream ends without a terminal event it falls through the `await for` and throws `StateError('SSE stream ended without a terminal event')` (`:159`). The `CancelledTerminal` return at `:154-155` is reachable only if a `CancelledEvent` *arrives on the wire* — which the architecture says cannot happen. T6 (`sdk_cancel_closes_stream`, `ai_client_sdk_test.dart:112-127`) passes because `FakeSseConnection.close()` and `DelayedFakeSseConnection.close()` push `const CancelledEvent()` into the stream before closing (`fakes.dart:152`, `:190`) — the test double teaches the implementation a contract the platform violates by design. FR-008, acceptance scenario 6, and the done-when "exposes cancel" are therefore unproven for the real wire: every E4 surface that awaits `session.terminal` after a user cancel will receive an untyped async error instead of the cancelled state.

2. **Transport retry is an unbounded, delay-free hot loop with no caller escape — a hanging platform hangs the client forever** (`frontend/lib/core/ai/ai_client_sdk.dart:42-69`). `invoke()` wraps submit in `while (true)`, and `on TransportFailure { continue; }` (`:66-67`) re-submits immediately: no retry ceiling, no backoff, no jitter, no timeout, and no cancellation path, because the `AiInvokeSession` — the only cancel handle — is returned only *after* a stream opens. A network partition, a DNS failure, or a down Worker therefore produces an infinite loop of immediate HTTPS submits: the `invoke` future never completes, the calling UI action can never be cancelled or time out, and the client hammers an unreachable host as fast as the event loop turns. §4.1 authorizes "retry on transport errors," and the spec's Assumptions decline to invent *numeric* ceilings — but declining to pick a number does not sanction an unbounded zero-delay loop; the coverage rule (delivery plan §3.10 item 5) names retry ceilings as a boundary every slice must respect, and no boundary exists here at all. T26 (`ai_client_sdk_test.dart:190-209`) scripts exactly one failure then success, so the loop's actual failure-mode behaviour — repeated failures, delay, give-up — is entirely unexercised.

## Bugs

1. **The session consumes and re-exposes the same stream — any single-subscription production `SseConnection` breaks on the first caller listen** (`frontend/lib/core/ai/ai_client_sdk.dart:106`, `:116`; `frontend/lib/core/ai/ports.dart:51-56`). The `AiInvokeSession` constructor subscribes to `connection.events` to drive the terminal future (`:106`), and the public `events` getter returns that same stream object (`:116`). The port contract (`ports.dart:51-56`) says nothing about broadcast semantics; an HTTP SSE response is naturally single-subscription, so a production port implementer following the contract as written produces a stream where the SDK's internal listen succeeds and any caller's `session.events.listen(...)` — the exact usage T27/FR-002's "surface stream events as received" implies, and the one E4's provisional rendering will need — throws `Bad state: Stream has already been listened to`. Only the fakes' `asBroadcastStream()` (`fakes.dart:127`, `:164`) hides this. The contract must either document the broadcast requirement or the SDK must rebroadcast internally.

2. **A stream that ends without a terminal event — network drop, proxy reset, server crash — surfaces as a bare `StateError` with no request reference and no typed state** (`frontend/lib/core/ai/ai_client_sdk.dart:158-159`). §5.5 rule 5 explicitly contemplates the connection lost mid-generation ("a connection lost mid-generation loses that generation and the user retries"), and rule 4 forbids inferring an outcome from silence — but the SDK's alternative to inference is an untyped `StateError`, which callers cannot distinguish from a programming defect and which carries neither the request reference (already recorded from `accepted`) nor any retry-safety signal. Stream *errors* from the source propagate raw through the same future. There is no `TransportFailure`-style typed outcome for "the stream died before its terminal event," so every caller must catch bare `Error` types to implement §5.4's "offer retry" behaviours.

3. **AAT acquisition and remint race under concurrency — cache stampede on cold start, N remints for N concurrent 401s** (`frontend/lib/core/ai/ai_client_sdk.dart:72-80`, `:60-64`). `_acquireAat` check-then-mints with no in-flight deduplication: two concurrent `invoke` calls on a cold cache both observe `null` and both mint. Symmetrically, `reminted` is per-invoke, so N concurrent submissions that all receive `unauthenticated` each null the cache and each remint once — N mints where one would do — and the `reminted = true; _cachedAat = null; continue;` sequence (`:61-63`) can mint a token that a racing invoke has already replaced. The single-flight desktop usage pattern makes this low-frequency, but the SDK is the shared transport for every future surface, and the fix (an in-flight mint future) is cheap.

4. **Idempotency keys and trace ids are 64/104-bit values from a non-cryptographic PRNG** (`frontend/lib/core/ai/ai_client_sdk.dart:88-96`). `_defaultIdempotencyKey` produces 16 hex chars (64 bits) from `dart:math` `Random()`. The idempotency key is the value B4's Durable Object uses to deduplicate requests — a collision silently returns a *prior* request's record instead of executing the new one — and 64 bits from a non-secure generator is thinner than the UUID-class identifiers the rest of the platform uses for correlation. Low probability, high blast radius, trivial fix (`Random.secure()` and/or 128+ bits).

## Architectural Deviations

1. **No architectural deviations found in E2's own behaviour.** The SDK is transport-only as §4.1 requires (no prompt text, provider names, model identifiers, or output transformation — confirmed by reading all four library files); the taxonomy mirror adds no codes and changes none; cancel is connection-scoped with no separate endpoint in the port surface; unknown codes map to `internal_error` per A2. Two documentation-level mismatches are recorded instead: (a) the delivery plan's done-when and §3.11.5 say "retains the last **N** request references" while §4.1 says "hold the **last** request reference" — the architecture wins, the implementation retains exactly one (`ai_client_sdk.dart:31-34`), and the spec's Independent Test section already records this reconciliation, so the mismatch is the delivery plan's to fix, not the slice's; (b) E2's spec freezes the SSE consumption rules for the single-shot kinds (`completed` / `failed` / `cancelled`) and declares conversational handling Out of Scope, yet the merged checkout's E2 files carry `ContextRequestedEvent`/`ContextRequestedTerminal` (`sse_events.dart:56-60`, `:90-95`) and `conversationId` / `turnOrdinal` / `transcript` fields (`ports.dart:16-33`). Delivery plan §2.3 permits later slices to *extend* frozen contracts, so the code is legitimate H-band growth — but neither E2's spec/plan nor the files themselves note that these members postdate the slice, leaving E2's artifacts describing a surface narrower than the one on disk.

## Missing or Weak Tests

1. **T6's "no separate cancel endpoint" assertion is vacuous, and its cancelled-terminal proof is fake-shaped** (`frontend/test/unit/core/ai/ai_client_sdk_test.dart:112-127`; `frontend/test/unit/core/ai/fakes.dart:116-119`). `expect(submit.cancelEndpointCalled, isFalse)` asserts that `callCancelEndpoint()` — a test-only method on the fake that nothing in the SDK or ports can invoke — was not invoked; the structural proof (no cancel method exists on `SseConnection`) is real but is not what the test checks. The cancelled-terminal half relies on the fake injecting `CancelledEvent` on close (Critical 1). No test asserts the SDK synthesizes `CancelledTerminal` when a stream simply closes after `cancel()` — the behaviour the real wire requires.

2. **T27 never listens to the relayed events it exists to prove** (`frontend/test/unit/core/ai/ai_client_sdk_test.dart:210-233`). `sdk_does_not_interpret_model_output` sends a `partial_structured` chunk and asserts only that the *terminal payload* passes through unchanged; it never subscribes to `session.events`, so the chunk relay — the "surfaces stream events as received" half of the assertion — is entirely unobserved. A regression that dropped, reordered, or transformed `ContentChunkEvent`s would leave T27 green, and the test's non-listening is exactly what conceals Bug 1's double-subscription failure.

3. **The T7–T23 no-retry family covers only the stream-level `failed` path — the HTTP-error-body path has one case (`unauthenticated`) out of seventeen** (`frontend/test/unit/core/ai/ai_client_sdk_test.dart:129-144`). §5.4's HTTP column is normative and terminal codes also arrive as error bodies *before* a stream opens; the SDK's `PlatformHttpException` rethrow branch (`ai_client_sdk.dart:58-65`) is exercised only for `unauthenticated` (T2/T3). No case proves that an HTTP-level `installation_suspended`, `request_too_large`, `quota_exhausted`, etc. is surfaced without auto-retry and — critically — without triggering the remint path (a regression that broadened the remint condition past `unauthenticated` would be caught only for codes the parameterized family happens not to cover). The `_recordRequestReference(error.requestReference)` half of spec scenario 8 ("and/or a terminal error body") is likewise untested: T24 (`:146-161`) covers reference retention from a stream only.

4. **No negative "silence" case exists — the branch the architecture names most explicitly is the one branch never exercised** (`frontend/lib/core/ai/ai_client_sdk.dart:158-159`). T5's assertion text includes "completion not inferred from silence" (spec T5; §5.5 rule 4), but every stream in the suite ends with a terminal event; no test closes a stream after `accepted` (or mid-content) and asserts the SDK does *not* complete normally. The `throw StateError` branch has zero coverage, so neither its firing (the drop case, Bug 2) nor its absence (the inference prohibition) is proven.

5. **The remint retry's idempotency-key stability and fresh-token usage are unasserted, and the transport-retry boundary has no failure-mode case** (`frontend/test/unit/core/ai/ai_client_sdk_test.dart:30-46`, `:190-209`). T2 asserts mint and submit counts but never checks that the retry after remint carried the *same* idempotency key (the property T4 proves only for transport retries) or that the retry used the freshly minted token rather than the stale one. T4/T26 script one or two failures then success; no case exercises sustained transport failure, so the retry loop's boundary behaviour (Critical 2) is undefined *and* unobserved — the coverage rule's named "retry ceilings" boundary has neither an implementation nor a test.

## Recommended Improvements

1. **Fix the cancel contract first**: consult `_cancelled` in `_consumeToTerminal` (or complete the terminal future directly from `cancel()`) so a client-initiated close resolves to `CancelledTerminal` locally; remove the `CancelledEvent` injection from both fakes' `close()` methods and re-prove T6 against a stream that merely ends. Keep `CancelledEvent` only if some other path can legitimately deliver it, and document which.
2. **Bound the transport-retry loop**: add a small retry ceiling with backoff/jitter (record the chosen numbers as an implementation choice, as the Clarifications section already does for ports), and surface exhaustion as a typed transport failure carrying the idempotency key so the caller can offer a manual retry. Provide a cancel/timeout path for the submit phase — either return the session handle before the stream opens or accept a caller token — so a hanging submit is interruptible.
3. **Close the stream-sharing hole**: document broadcast semantics as a hard requirement on `SseConnection.events`, or rebroadcast inside `AiInvokeSession` so the terminal consumer and any number of event listeners cannot conflict; then strengthen T27 to actually collect `session.events` and assert the chunk sequence passes through unaltered.
4. **Type the drop path**: replace the bare `StateError` on terminal-less stream end (and raw stream-error propagation) with a typed outcome — e.g. `FailedTerminal(code: internalError)` or a dedicated transport-failure state — that carries the last recorded request reference, matching §5.5 rule 5's "the user retries" expectation.
5. **Enforce classification at the wire boundary**: make `FailedEvent` constructible from raw wire codes only through a factory (e.g. `FailedEvent.fromWire(String code, ...)`) that applies `classifyTaxonomyCode`, so FR-010's "never surfaced raw" holds for every future port implementation rather than depending on each implementer remembering to classify.
6. **Broaden the proof surface to match the spec's own scenarios**: add per-code HTTP-level no-retry cases (or one parameterized family mirroring T7–T23 against `SubmitHttpErrorStep`), an error-body reference-retention case for T24, a silence negative case for T5, and key-stability/fresh-token assertions on the remint retry in T2.
7. **Harden the token path under concurrency and at rest**: single-flight the mint in `_acquireAat` (share one in-flight mint future), deduplicate concurrent remints, and switch key/trace generation to `Random.secure()` with at least 128 bits for the idempotency key.
8. **Decouple the idempotency key from SDK construction**: allow the caller to supply (or rotate) the key per `invoke` so a user-initiated retry of the same action can reuse the original key — and so downstream slices stop working around the constructor-bound factory. `ConversationLoop._sdkForLeg` (`frontend/lib/core/ai/conversation_loop.dart:64-73`) already rebuilds the entire SDK per leg to get key rotation, silently discarding the AAT cache (a re-mint per leg) and the retained request reference; a per-invoke key parameter removes that workaround and its costs.
9. **Annotate the H-band growth in E2's files**: add a brief note to E2's spec/plan (or the affected classes) recording that the conversational members postdate the slice per §2.3's extend-don't-rewrite rule, keeping the slice's frozen surface auditable against the code on disk.

### 1.3 Fix implemented

- **Cancel:** `_consumeToTerminal` returns `CancelledTerminal` when `_cancelled` and the stream ends without a wire terminal; fakes' `close()` no longer injects `CancelledEvent` (kept as a defensive wire kind only).
- **Transport retry:** ceiling `maxTransportAttempts=3`, injectable backoff (default exponential + jitter), `TransportRetryExhausted(idempotencyKey, attempts)`, `invoke(cancelSignal:)` races submit/backoff.
- **Rebroadcast:** `AiInvokeSession` owns a broadcast relay over a single listen on `connection.events`; port contract documents that sources may be single-subscription.
- **Drop path:** new `StreamDroppedTerminal` (with request reference + optional cause, `retrySafe`); replaces bare `StateError`.
- **AAT:** shared `_inFlightMint` Future for cold and remint acquires.
- **Keys:** `Random.secure()`, 32 hex chars for default idempotency key and trace id.
- **Classification:** `FailedEvent.fromWire` applies `classifyTaxonomyCode`.
- **Per-invoke key:** optional `idempotencyKey` on `invoke`; `ConversationLoop` uses it and preserves the AAT cache across legs.
- **H-band note:** Clarification Session 2026-08-05 in Spec Kit + class/field doc-comments.
- Call sites updated for exhaustive `TerminalState` switches (`conversation_loop.dart`, `first_ai_feature_surface.dart`).

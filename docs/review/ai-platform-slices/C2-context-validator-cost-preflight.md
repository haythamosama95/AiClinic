# Slice Review Report — C2: Context Validator Stage and Cost Pre-Flight

**Spec:** `specs/026-context-validator-cost-preflight/spec.md` · **Branch:** `ai/026-c2-context-validator-cost-preflight` · **Canonical:** §4.3.5, §5.2, §4.3.3, §6.1 stages 6–7, §13.6.2

## Executive Summary

C2 delivers the modules its contract names — `src/context/validator.ts` (`validateContext`, `buildContextRequiredResponse`, `ValidateResult`) and `src/context/preflight.ts` (`estimateInputTokens`, `runCostPreflight`, the two §13.6.2 constants) — and all fifteen named tests are present in a single unit-spy suite. The core logic matches the frozen contract with unusual fidelity: the evaluation order (required keys → tenant → shape/size → filter), the full missing-key set in `context_required`, the `unknown_shape` tolerance, the byte-based estimator exactly as §13.6.2 fixes it, both stage-7 predicates in tokens with no currency anywhere, and undeclared-key dropping proven by spy are all implemented and asserted. The substantive defects are fail-open coercions rather than wrong logic: a non-numeric `maxOutputTokens` turns the ceiling comparison into string concatenation and a `NaN` disables both pre-flight predicates outright, and the same `Number()` coercion pattern disables the per-key size bound and (via `=== true` on an unchecked field) required-key enforcement — A4's loader validates presence of these fields but never their types, so a malformed manifest silently switches off every bound this slice exists to enforce. Since C2 froze its contract, H2 has merged the conversational transcript machinery into `validator.ts` — a fourth `ValidateResult` branch the contract explicitly forbids, a fourth function parameter, and three unlisted exports — without amending the artifact D1/J2/B4 are bound to consume, the same drift pattern as C1's J1 merge. Coverage meets the named-test floor but never touches an exact boundary (== ceiling, == maxInputTokens, == maxSize), the contract-pinned evaluation-order short-circuit, the absent-org/branch case, the same-concept-different-version edge the spec calls out, or any malformed-manifest path, and nothing asserts the immutability of either output payload.

## Critical Issues

None. Both done-when criteria are met at the library level this slice scopes itself to: the validator enforces presence, shape, size, and tenant consistency and drops undeclared keys; the pre-flight checks the token-denominated ceiling before any egress and the spy tests prove zero downstream calls on rejection. As with C1, no stage-6/7 wiring exists in `worker.ts` (no consumer of `validateContext` or `runCostPreflight` anywhere in `src/`) — consistent with contract §10 deferring consumption to D1/B4/D3, an observation rather than a defect here. The fail-open coercions below require a malformed platform-published manifest, which keeps them out of critical territory, but they disable the exact controls the slice exists to provide.

## Bugs

1. **The cost pre-flight fails open on non-numeric Economics fields — a malformed manifest silently disables the ceiling it exists to enforce** (`ai-platform/src/context/preflight.ts:24-33`). `runCostPreflight` destructures `maxOutputTokens`, `maxInputTokens`, and `perRequestCostCeiling` and uses them raw in arithmetic. If `maxOutputTokens` is a string, `estimatedInputTokens + maxOutputTokens` is string *concatenation* (`28.75` + `"1024"` → `"28.751024"`), and the subsequent `>` coerces that string back to a number — a comparison against garbage. If any of the three is `undefined` or otherwise non-numeric, the arithmetic yields `NaN`, both `>` predicates are `false`, and the pre-flight passes every request regardless of size. A4's loader checks only that the four Economics keys are *present* (`ai-platform/src/manifest/index.ts:164-174`, `:352-356`), never that they are numbers, so this state is reachable through the normal load path. The one control whose entire job is bounding per-request cost (§4.3.3, §13.6.2) should fail closed — reject, or throw at manifest load — not wave the request through to a paid provider call.

2. **The per-key size bound and required-key enforcement fail open the same way** (`ai-platform/src/context/validator.ts:303-307`, `:313`, `:350-352`). `Number(entry.maxSize)` is `NaN` for a missing or non-numeric `maxSize`, and `jsonByteLength(value) > NaN` is always `false` — the oversize check never fires. Symmetrically, `entry.required === true` treats any truthy non-boolean (`"yes"`, `1`) as *optional*, silently dropping a required key from the missing-key manifest. A4's single-shot entry validation is again presence-only (`ai-platform/src/manifest/index.ts:176-193`). Each is individually a manifest-authoring defect, but the validator is the enforcement point §4.3.5 names, and "sizes within bounds, required keys present" should not depend on the manifest author never mistyping a field the loader never type-checks.

3. **A manifest-declared key absent from the published vocabulary is rejected as `context_invalid` — a platform defect billed to the client** (`ai-platform/src/context/validator.ts:345-348`; `ai-platform/src/context/index.ts:195-209`). `validatePayload` runs `validateKey` first, which rejects keys outside the six-entry `PUBLISHED_CONTEXT_KEYS` set with `unknown_version` (and malformed/storage-named keys likewise); the validator tolerates only `unknown_shape` and maps everything else to `context_invalid` — 422, not retryable, client behaviour "Bug: report with request reference" (§5.4). But a manifest declaring an unpublished key is the *platform's* defect: the client cannot remedy it, and §5.4's `internal_error` ("Platform defect", retry-safe) is the honest code. Contract §3.4 froze the `!== "unknown_shape"` predicate without separating these two fault domains; the predicate should distinguish "shape violation the client can fix" from "manifest the platform published wrong."

4. **The published-shape registry is duplicated, so the missing-key manifest can silently omit shapes A5 publishes** (`ai-platform/src/context/validator.ts:62-68` duplicating `ai-platform/src/context/index.ts:69-71`). `validator.ts` keeps its own `PUBLISHED_SHAPES` map for `buildShapesForMissingKeys` while the authoritative `PUBLISHED_KEY_SHAPES` lives in the A5 module it already imports from. The next shape A5 publishes will be enforced by `validatePayload` but absent from the `context_required` payload's `shapes` member — degrading the §8.4 self-healing handshake ("missing keys + shapes") with no test or type error to catch it. The validator should import a lookup from the A5 module rather than maintain a second copy.

5. **Neither output payload is frozen, and both share mutable references with their inputs** (`ai-platform/src/context/validator.ts:356-364`, `:367-385`). The spec's clarification freezes "a frozen snake_case missing-key manifest" (spec.md:51), but `buildContextRequiredResponse` returns a plain object whose `missing_keys` and `shapes` are the very array and record on the `ValidateResult` — a caller mutating the wire body mutates the stage result. `filteredContext` is likewise an unfrozen shallow assembly whose nested values alias the caller's `suppliedContext`, so a downstream stage (the composer, D1) that mutates a nested value mutates the caller's object. C1 treated manifest immutability as a tested invariant; C2's handed-forward payloads — the artefact its "Freezes" section exists to define — have no equivalent discipline.

## Architectural Deviations

1. **H2's conversational machinery is merged into `validator.ts` without amending the frozen contract — the same drift pattern as C1's J1 merge.** (a) `ValidateResult` has a fourth branch, `conversation_budget_exhausted` (`ai-platform/src/context/validator.ts:48`), which contract §2 explicitly forecloses ("No other failure codes are emitted by `validateContext()`", contracts/context-validator.md:45-46). (b) `validateContext` gained a fourth parameter, `conversational?: ConversationalValidateOptions` (`validator.ts:281-296`), against the contract's three-argument signature (§2, §9.1). (c) `TranscriptTurn`, `Transcript`, and `ConversationalValidateOptions` are exported (`validator.ts:17-53`) though contract §9.1's export surface omits them. (d) The spec's own Out-of-Scope section assigns all of this to H2 ("An `interaction_mode: conversational` manifest is not validated by this slice," spec.md:148). The code itself matches the architecture — §4.3.5's conversational paragraph and §5.4's `conversation_budget_exhausted` row sanction every behaviour — so, as with C1, the code is right and the frozen artifact is stale; what may not stand is D1/J2/B4 consuming a contract that misdescribes the union they must switch on.

2. **The estimator's measured input is narrower than §13.6.2 — prompt artifacts are architecturally included but the contract and signature give no way to include them** (`ai-platform/src/context/preflight.ts:20-23`; contracts/context-validator.md:162-186). §13.6.2 is explicit: the input under measurement is "the validated and filtered context payload, the caller's intent, and — for `conversational` — the submitted transcript. **Prompt artifacts bound to the capability are included at their known byte length**" (docs/architecture/17-ai-platform.md:3659-3661). `runCostPreflight(manifest, serializedInput)` takes one opaque string; nothing in the signature, the contract, or FR-007 ("over the filtered context plus the caller's intent," spec.md:121) accounts for artifact bytes, and the transcript is the caller's undocumented burden. Since no caller exists yet, this is a latent under-estimate by the system-instruction and rule-fragment byte length — precisely the fixed overhead that dominates small clinic requests — baked into a frozen signature D3 will consume. Architecture wins: either the function takes the artifact byte length (it is known at compose time and constant per manifest) or the architecture text is amended deliberately.

3. **The §8.4 "missing keys + shapes" promise is vacuous for every key that can currently trigger it** (`ai-platform/src/context/index.ts:60-71`; fixture at `ai-platform/test/context-validator.test.ts:62-84`). Exactly one shape is published — `visit.chief_complaint@v1` — and in the only manifest fixture (and the only OD-1 capability) that key is *optional*, so it can never appear in `missing_keys`. Both required keys (`patient.demographics@v1`, `visit.vitals@v1`) have no published shape, so the `shapes` member of every `context_required` payload the platform can emit today is empty, and shape *enforcement* for required keys is equally vacuous (`unknown_shape` passes, `validator.ts:346`). This is an A5 vocabulary gap C2 inherits rather than a C2 defect, but it belongs on record before J2 wires client self-healing against a payload whose `shapes` is always `{}` — the stale client will recover the key names and nothing else.

4. **Stages 6–7 are unwired** (no reference to `validateContext`, `runCostPreflight`, or `buildContextRequiredResponse` in `ai-platform/src/worker.ts` or anywhere in `src/` outside the module). Consistent with contract §10 deferring consumption — but worth restating, as the C1 report did, because the "no egress on rejection" done-when is currently proven only against the test harness's own spy (`test/context-validator.test.ts:36`, `:238-247`), not against a pipeline in which stage 7 actually precedes stage 11.

## Missing or Weak Tests

1. **No exact-boundary test exists for any named limit** (`test/context-validator.test.ts:593-729`). The coverage rule demands every named boundary; the suite has none. T-C2-10 passes with values far under the ceiling, T-C2-11 far over it, and T-C2-15 sets `maxInputTokens` to `Math.floor(estimate)` — strictly below, never equal. The `≤` in both stage-7 predicates (estimate + maxOutput == ceiling must *pass*; estimate == maxInputTokens must *pass*) and the `>` in the per-key size check (bytes == maxSize must pass; T-C2-05 tests only over) are unasserted — an off-by-one flip to `<` in any of the three comparisons would turn no test red.

2. **The contract-pinned evaluation-order short-circuit is untested** (contracts/context-validator.md:55-64). No test combines a missing required key with a tenant mismatch or a shape violation to prove the outcome is `context_required` (and only that) — the ordering is the entire reason the self-healing payload is trustworthy when several things are wrong at once, and a reordering would be invisible to the suite.

3. **Absent `org`/`branch` in the supplied context is untested** (`ai-platform/src/context/validator.ts:331-336`). Absence is a mismatch (`undefined !== principal.organizationId` → `context_invalid`), which is the correct fail-closed reading of §5.2 Authorization — but no test pins it, so a "helpful" change to skip the tenant check when the fields are absent would pass the suite.

4. **The spec's same-concept-different-version edge case is untested** (spec.md:105). T-C2-06 drops `medication.active_list@v1`, a wholly unrelated key; the named edge — supplying `visit.vitals@v2` where the manifest declares `visit.vitals@v1`, which must be *dropped as undeclared* (and, since v1 is required, must also surface in `missing_keys`) — has no case.

5. **No malformed-manifest path is tested** (Bugs 1–2). Every fixture flows through `load()` with well-typed numbers and booleans; the fail-open coercions on non-numeric Economics, missing `maxSize`, and non-boolean `required` are unreachable in the suite, so the tests prove the bounds work only for manifests that never needed defending against.

6. **No immutability assertion on either output payload** (Bug 5). Contrast C1's T-C1-06, which attempts writes against the resolver's result; nothing here attempts mutation of `filteredContext` or the `context_required` wire body, and the shared-reference aliasing would make such a test fail today.

7. **The `unknown_shape` tolerance and the `unknown_version` rejection are only implicitly covered** (`ai-platform/src/context/validator.ts:345-348`). T-C2-01 passes two shape-less required keys without ever asserting *why* they pass; no test declares a key outside the published vocabulary to pin the `context_invalid` outcome of Bug 3 — whichever way Bug 3 is resolved, the behaviour should be pinned deliberately.

8. **T-C2-14's `expectedEstimate` helper re-implements the formula under test** (`test/context-validator.test.ts:144-150`). For the ASCII case the test computes the estimate by the same expression as the source, so a coordinated change to both constants in both files would pass; only the multi-byte case anchors against literals (`Math.ceil(5 / 4) * 1.15`, `:697-700`). A table of fixed input→estimate literals would make the determinism guarantee independent of the implementation.

## Recommended Improvements

- **Fail closed on malformed economics and context-requirement entries** (Bugs 1–2): type-check `maxInputTokens`/`maxOutputTokens`/`perRequestCostCeiling` as finite numbers and `required`/`maxSize` as boolean/number at manifest load (A4's `validateObjectGroup`/`validateSingleShotContextRequirements`), so a malformed manifest fails the build rather than disabling the bounds at runtime; until then, have `runCostPreflight` and the validator treat non-numeric bounds as rejection, not pass.
- **Resolve Bug 3's fault assignment**: split the `validatePayload` failure codes into client-remediable (shape violations → `context_invalid`) and platform-side (unpublished/malformed declared key → `internal_error` or a load-time failure), and amend contract §3.4 accordingly.
- **Single-source the published shapes** (Bug 4): export a `publishedShapeForKey` lookup from `src/context/index.ts` and delete the duplicate map in `validator.ts`.
- **Freeze and copy the output payloads** (Bug 5): deep-freeze (or at least shallow-freeze with copied `missing_keys`/`shapes`) the `context_required` wire body, and freeze `filteredContext`; add the mutation tests.
- **Amend the frozen contract for the H2 merge** (Deviation 1): add the `conversation_budget_exhausted` branch, the fourth parameter, and the three new exports to §2/§9.1, exactly as C1's contract owes the J1 lifecycle amendments.
- **Close the estimator-input gap** (Deviation 2): decide how prompt-artifact bytes enter the measured input — a third parameter, or a manifest-derived constant — and amend FR-007 and contract §6–7 to match §13.6.2 before D3 consumes the signature.
- **Add the missing cases**: exact-equality boundaries for all three comparisons; evaluation-order short-circuit; absent org/branch; same-concept different-version key; malformed-manifest fail-closed paths; payload immutability; literal-anchored estimator table.

# Slice Review Report — E4: First AI Feature Surface and Degraded Mode

**Spec:** `specs/038-first-ai-feature-surface/spec.md` · **Branch:** `ai/038-e4-first-ai-feature-surface` · **Canonical:** §4.1, §6.4, §13.2, §4.2, §5.4, A11

## Executive Summary

E4 delivers the module set its plan names: an `AiAvailability` model and injectable reader over a new `public.get_ai_availability()` clinic RPC (defaulted fail-closed to non-enrolled), a six-state `AiDegradedMode` enum with a normal-state `AiDegradedView`, a `FirstAiFeatureSurface` that renders provisional prose with draft styling and enables accept/discard only after terminal `completed`, a `RequestReferenceView` shown on failure, a standalone `AiFeatureHostPage` composing the availability gate with the surface, and a widget suite covering the twenty-one named tests. The frozen behaviours that exist as code are mostly correct in isolation: provisional content is genuinely ephemeral (it lives only in widget `State`), the terminal payload is authoritative (chunks are never assembled into the answer), and the non-enrolled path returns before any reachability probe. The substantive failures are in wiring rather than in the widgets. First, the §5.4 client-behaviour mapping (quota exhausted, installation suspended, forbidden capability, AI unavailable) is driven exclusively by a `terminalFailureCode` constructor parameter that has no production source and is never fed by an actual terminal outcome — the surface's own failure path renders only a bare reference line — so four of the six degraded states are dead code outside the test harness, and A11's distinct first-class states are demonstrated only by injecting the enum. Second, the registered production route renders a placeholder string, not `AiFeatureHostPage`, so the availability gate and the surface have no production call site at all. Third, the surface subscribes to raw stream events but fire-and-forgets `session.terminal`: a stream that ends without a terminal event (the exact network-drop case §5.5 rule 5 describes) throws inside the SDK's terminal completer, the error is unhandled, and the surface is left displaying provisional draft text forever with no failure state and no request reference. Finally, several of the prohibition tests are vacuous or self-reported: the persistence/export probes are never invoked by any production code path, and the "no network call" spy in T8 counts only calls the host records about itself.

## Critical Issues

1. **The §5.4 client-behaviour mapping is wired to a test-only seam — quota/suspended/forbidden/unavailable degraded states can never occur outside the widget suite** (`frontend/lib/features/ai/host/ai_feature_host_page.dart:58`, `:100-106`; `frontend/lib/features/ai/surface/first_ai_feature_surface.dart:244-245`). `AiFeatureHostDependencies.terminalFailureCode` is a constructor-injected constant; nothing in the surface, the SDK consumption, or any production path ever supplies it. The host's `_bootstrap` resolves the degraded mode once from this injected value, so `quotaExhausted`, `installationSuspended`, `forbiddenCapability`, and `aiUnavailable` are reachable only when a test constructs the dependencies with the code pre-loaded (as T11/T12/T18/T19 do). Meanwhile the surface's real failure path — a terminal `FailedEvent` carrying, say, `quota_exhausted` or `installation_suspended` — goes to `_setFailed`, which renders only `RequestReferenceView` (`first_ai_feature_surface.dart:244-245`); it never maps the code to the distinct quota state with the admin path, never hides the affordance, and never notifies the host. A11 requires "AI unavailable, quota exhausted, and offline are distinct, first-class UI states," FR-010/FR-013 require applying the §5.4 Client behaviour column, and the §5.4 rows for `quota_exhausted` ("Show quota state, offer admin path"), `installation_suspended` ("Hide AI features; instruct admin"), and `forbidden_capability` ("Hide the affordance for this role") are all satisfied only in a harness that injects the answer. The degraded-mode machinery and the failure stream it exists to interpret are never connected.

2. **The production route renders a placeholder, not the host — the availability gate and surface have no production entry point** (`frontend/lib/app/router.dart:98-105`; `frontend/lib/features/ai/host/ai_feature_host_page.dart:63-70`). `AppRoutes.aiFeatureHost` (`frontend/lib/app/app_routes.dart:165`) is registered with a builder returning `Scaffold(body: Center(child: Text('AI feature host route is registered for CP3 composition.')))`. `AiFeatureHostPage` is instantiated only by the widget-test harness. Clarification Q2 scoped the host as "standalone host shell/route under `features/ai/` for tests + CP3 entry," and tasks.md T018 ("register host route") is checked complete — but the route that exists does not host the feature, so the Done-when's "enrolled and reachable shows affordances" cannot occur in the running app, and the CP3 falsification thread with D4 has no client entry. If the deferral to CP3 composition is deliberate, the tasks/plan record should say the route is a stub; as built, T018's claim and the implementation disagree.

3. **A stream that ends without a terminal event leaves provisional content on screen forever, and the SDK's terminal error is an unhandled async exception** (`frontend/lib/features/ai/surface/first_ai_feature_surface.dart:138-171`; `frontend/lib/core/ai/ai_client_sdk.dart:129-160`). The surface listens to `session.events` and then does `unawaited(session.terminal)` (`first_ai_feature_surface.dart:171`). Inside the SDK, `_consumeToTerminal` throws `StateError('SSE stream ended without a terminal event')` when the source closes without a terminal event (`ai_client_sdk.dart:159`) — which is precisely what a mid-generation network drop looks like on the client, since the platform treats a dropped connection as a cancel and the client's socket simply dies (§5.5 rule 5). Nobody awaits that future: the error surfaces as an unhandled asynchronous exception, and the surface's own event listener just sees the stream stop — no `FailedEvent`, no `CancelledEvent` — so `_phase` remains `streaming` and the provisional draft text stays rendered indefinitely, with no failure state and no request reference. The Done-when ("the request reference is displayed on every failure") and §5.5 rule 4 ("one terminal event, never inferred from silence") both require the client to settle this case; the surface neither settles it nor reports it.

## Bugs

1. **Provisional rendering replaces rather than accumulates deltas — a multi-chunk stream shows only the last fragment** (`frontend/lib/features/ai/surface/first_ai_feature_surface.dart:146-155`). On each `text_delta`, `_provisionalText = chunk` overwrites the prior provisional text. Real `prose` streams emit many deltas; the user would see only the most recent fragment flickering rather than the accumulating draft §6.4's "Display live" client rule describes. Terminal-payload authority (invariant 1) is preserved — the final answer still comes from `completed` — but the live-display branch is wrong for every stream longer than one chunk, and every test feeds exactly one chunk (`ai_surface_test_harness.dart:150-159`), so the suite cannot see it.

2. **Fabricated request references are displayed to users as support handles** (`frontend/lib/features/ai/surface/first_ai_feature_surface.dart:121-124`, `:174-176`). On a context-resolver failure the surface calls `_setFailed(code: TaxonomyCode.contextInvalid, requestReference: widget.sdk.lastRequestReference ?? 'ctx-fail')`, and the catch-all does the same with `'invoke-error'`. When the fallback fires, the user is shown `Reference: ctx-fail` — a string that resolves to nothing in the platform journal. A13 exists so support can resolve "the user says my request failed" from the reference read aloud; a fabricated constant is worse than an honest local-failure message because it sends support hunting for a trace that does not exist (§13.2). The misclassification compounds it: a client-side resolver failure is not `context_invalid`, which §5.4 defines as platform-side rejection of supplied context shape. The same `contextInvalid` mapping is applied to `ContextRequestedTerminal` (`first_ai_feature_surface.dart:196-201`) — an event kind a `single_shot` capability can never receive (§5.5 rule 4) — inventing a taxonomy outcome the platform did not emit, contrary to FR-013's "adds no taxonomy codes and changes none" posture.

3. **Terminal `cancelled` is ignored — the §5.4 "Return to idle" client behaviour is not applied** (`frontend/lib/features/ai/surface/first_ai_feature_surface.dart:167-169`, `:193-194`). `CancelledEvent` in the stream listener and `CancelledTerminal` in `_onTerminal` both fall into `break` with no state change. If the stream delivers a cancellation while the widget is alive (the fakes' own `close()` emits `CancelledEvent` into the stream — `frontend/test/unit/core/ai/fakes.dart:148-155`), the surface stays in `streaming` with the provisional draft still displayed. §5.4's row for `cancelled` names the client behaviour: "Return to idle." No test exercises this path, so the gap is invisible to the suite.

4. **The host bootstrap has no error handling — a failed availability read pins the page on a loading spinner forever** (`frontend/lib/features/ai/host/ai_feature_host_page.dart:83-115`, `:119-121`). `_bootstrap` awaits `availabilityReader.read()` with no `try`/`catch`; `SupabaseAiAvailabilityReader.read()` (`frontend/lib/features/ai/availability/ai_availability_reader.dart:17-27`) propagates any RPC/Decoding exception. An exception in the `initState`-launched future leaves `_loading` true permanently and surfaces as an unhandled async error — on a slice whose entire purpose is that AI failure "renders as a normal state rather than an error dialog" and never blocks clinical work (A11). The fail-closed default (`AiAvailability.nonEnrolled`) exists in the model but is never applied on the error path.

5. **Two §5.4 client behaviours are mapped to the wrong presentation** (`frontend/lib/features/ai/degraded/ai_degraded_mode.dart:34-39`). `capabilityUnknown` and `capabilityRetired` resolve to `aiUnavailable`, whose message is "AI is temporarily unavailable." (`ai_degraded_view.dart:70`); §5.4's Client behaviour for both is "Prompt for app update" — a materially different instruction (temporary vs. permanent-with-remedy). `providerUnavailable` resolves to the same state, but §5.4 says "Offer retry; degraded notice," and no retry affordance exists in either the degraded view or the surface. FR-013 requires applying the Client behaviour column for outcomes the surface presents.

6. **The migration omits the established `REVOKE` on the `auth_internal` definer function** (`backend/supabase/migrations/20260802140000_ai_availability_flag.sql:10-38`). Every comparable migration revokes EXECUTE on the `auth_internal` SECURITY DEFINER half from `PUBLIC, authenticated, anon` (e.g. `20260605180000_billing.sql:863-871`, `20260724120000_patient_mrn_field.sql:40`); PostgreSQL grants EXECUTE to `PUBLIC` on new functions by default, so `auth_internal.get_ai_availability()` remains directly callable, bypassing the `public` wrapper's grant discipline the F4 pattern exists to enforce. The exposure is low (the function reads one settings row), but it breaks the clinic's uniform wrapper-gate pattern.

7. **Dead conditional in the surface build method** (`frontend/lib/features/ai/surface/first_ai_feature_surface.dart:258`). `if (_failureCode != null && _failureCode != TaxonomyCode.contextInvalid) const SizedBox.shrink()` renders nothing in all cases and reads like a leftover from a removed per-code failure presentation — consistent with Critical 1's observation that the surface never branches failure rendering on the taxonomy code.

## Architectural Deviations

1. **The surface consumes raw stream events in parallel with the SDK's own consumption — the pairing only works against broadcast streams, which real SSE connections are not** (`frontend/lib/core/ai/ai_client_sdk.dart:105-118`, `:129-130`; `frontend/lib/features/ai/surface/first_ai_feature_surface.dart:138`). `AiInvokeSession`'s constructor immediately subscribes to `connection.events` via `_consumeToTerminal`; E4's surface then calls `session.events.listen(...)` on the same underlying stream. Every fake in the suite converts to a broadcast stream (`fakes.dart:129`, `:164`), masking that a single-subscription SSE source — the natural implementation of the `HttpsSubmitPort` production adapter when it lands — will throw "Stream has already been listened to" on the second subscription. §4.1 assigns the SDK "consume the event stream, surface terminal state"; E4's surface re-consuming the raw stream is exactly the dual-consumer shape the port abstraction does not support. The surface should be driven from `session.terminal` plus an SDK-exposed chunk stream, or the SDK should expose a single broadcast.

2. **The required context keys are hardcoded in the surface instead of coming from capability discovery** (`frontend/lib/features/ai/surface/first_ai_feature_surface.dart:15`, `:121`). The surface pins `kFirstAiCapabilityId = 'clinic.visit_summary'`, version `'1.0.0'`, and resolves a fixed `[visitChiefComplaintV1Key]` list. §5.5 states capability discovery "drives the Context Resolver," and the manifest is the authority on which keys a capability requires (§5.1) — a manifest that adds a required key would silently produce `context_required` failures until the client is edited, which is the per-feature-glue drift §4.1's generic-registry emphasis exists to prevent. The spec froze the first capability identity, so pinning the id is defensible; duplicating the manifest's context declaration in client code is a narrowing of the architecture the spec never flags, and the architecture wins.

3. **The surface disposes a `ContextResolver` it does not own** (`frontend/lib/features/ai/surface/first_ai_feature_surface.dart:103-109`; `frontend/lib/features/ai/host/ai_feature_host_page.dart:110-114`). The host creates the resolver and passes it in; the surface's `dispose()` calls `widget.resolver.dispose()`. Ownership inversion is benign in the current single-surface composition but breaks the moment a host reuses a resolver across surfaces or rebuilds — the E3 contract's screen-scoped cache lifetime then ends whenever any one surface unmounts.

4. **A non-enrolled installation is shown an AI banner, where the architecture says hide AI chrome entirely** (`frontend/lib/features/ai/degraded/ai_degraded_view.dart:67`; `frontend/lib/features/ai/host/ai_feature_host_page.dart:131-146`). §4.2's flag exists so "the client can hide AI affordances entirely for non-AI clinics," and the spec's own Constitution Alignment states "Non-enrolled clinics never see AI chrome." The host instead renders `Ai is not enabled for this clinic.` — and T8 asserts that container is present (`ai_degraded_mode_test.dart:20-21`), freezing the deviation into the suite. On the standalone route this is mild, but the message container is AI chrome shown to a non-AI clinic, and if this host is later embedded per Clarification Q2's successor, the banner pattern will travel with it.

## Missing or Weak Tests

1. **T16/T17 are vacuous — the persistence and export probes are never invoked by any production code path** (`frontend/lib/features/ai/surface/first_ai_feature_surface.dart:24-60`, `:213-227`; `frontend/test/widget/ai/first_ai_feature_surface_test.dart:210-239`). `AiPersistenceProbe.recordWrite` and `AiExportProbe.recordExport` have no call sites anywhere in `frontend/lib` — not in the accept path, the discard path, or the streaming path. The tests assert `probes.writes isEmpty` / `exports isEmpty`, which holds trivially for a probe nothing can write to. A spy proves "work not done" (delivery plan §3.10) only when the work, if done, would pass through the spy; here a future regression that persisted provisional text through any real channel would leave both tests green. The tests prove the widget contains no persistence code today — which reading the file establishes more cheaply — not that the prohibition is enforced.

2. **T8's "no network call" assertion is self-reported by the code under test** (`frontend/lib/features/ai/host/ai_feature_host_page.dart:96-99`; `frontend/test/widget/ai/ai_degraded_mode_test.dart:13-23`). The `networkSpy` is fed by the host itself (`widget.dependencies.networkSpy?.recordPlatformCall(...)`), so the test asserts that the host recorded zero calls — a non-enrolled-branch regression that probed the network without recording would pass. The honest spy already exists: `FakePlatformReachabilityPort.callCount`, which T21 asserts (`ai_degraded_mode_test.dart:34`) but T8 does not. As written, T8's spy proves the recording statement sits inside the enrolled branch, not that the network is untouched.

3. **No test drives a terminal failure code from the SDK through to a degraded state** (`frontend/test/widget/ai/ai_degraded_mode_test.dart:65-112`). T11/T12 pump `AiDegradedView` directly with an enum value; T18/T19 inject `terminalFailureCode` into the host dependencies. No test submits a stream whose terminal `FailedEvent` carries `quota_exhausted` / `installation_suspended` / `forbidden_capability` / `provider_unavailable` and asserts the resulting UI — because (Critical 1) no such wiring exists. The §5.4 Client-behaviour branches are therefore tested at the enum boundary, not at the behaviour the slice ships; under §3.10 ("every branch of every rule … behaviourally") the show-quota, hide-features, and hide-affordance branches have no end-to-end proof.

4. **The stream-termination and cancellation paths are untested** (`frontend/test/widget/ai/first_ai_feature_surface_test.dart:20-240`). There is no test for a connection that closes without a terminal event (Critical 3), none for a terminal `cancelled` reaching a live surface (Bug 3), and none for a failure carrying a null request reference (the `RequestReferenceView` is conditional on `_requestReference != null`, `first_ai_feature_surface.dart:244`, so FR-006's "every failure" has an uncovered null-reference branch). `cancelled` is also a §5.4 code the surface can emit — §3.10's every-error-code rule asks for one case.

5. **Multi-delta streaming is untested** (`frontend/test/widget/ai/ai_surface_test_harness.dart:150-159`). Every scripted stream emits at most one `text_delta` before `completed`. The replace-instead-of-accumulate defect (Bug 1) lives in the branch the suite never exercises, and §3.10's happy-path coverage of "display live" is proven at a single chunk.

6. **T20 spawns the guard over the whole tree, not the slice's surface** (`frontend/test/widget/ai/ai_surface_test_harness.dart:161-170`). `runArchitectureGuardOnFeaturesAi` runs `dart run tool/architecture_guard/architecture_guard.dart` with default roots (`lib`, `test`) and expects exit 0. It would catch a violation under `features/ai/`, but only by re-proving the entire clean tree — a violation anywhere else in `frontend/lib` (unrelated to E4) would fail this slice's named test, coupling T20's signal to the whole codebase, and it duplicates rather than complements the CI gate. It also depends on `dart` being on the test runner's `PATH` and on the process working directory heuristic (`File('pubspec.yaml').existsSync()`), which the test name gives no hint of.

## Recommended Improvements

1. **Wire terminal outcomes to the degraded-mode map**: have the surface report its terminal `FailedEvent` code upward (callback or shared controller), let the host resolve `resolveDegradedMode` from that real code, and render the distinct quota/suspended/forbidden/unavailable states from actual failures — then rewrite T11/T12/T18/T19 to drive a `FailedEvent` through the SDK and assert the resulting state, deleting the `terminalFailureCode` injection seam.
2. **Settle the terminal contract on the surface**: await `session.terminal` (or handle the stream's `onDone`/`onError`) and map a terminalless close to a failure state displaying the last request reference from `sdk.lastRequestReference`; apply the §5.4 `cancelled` row ("Return to idle") when a live surface observes cancellation. This closes Critical 3 and Bug 3 together and gives the unhandled `StateError` a catch.
3. **Accumulate provisional deltas** (`_provisionalText += chunk` or a buffer) so live display matches §6.4's "Display live," and add a two-chunk stream case to the suite to keep it honest.
4. **Remove the fabricated references**: client-side failures (resolver failure, invoke exceptions) should render a local-failure state with no fake reference — or a real reference only when the SDK actually recorded one — and stop mapping them to `context_invalid`, which §5.4 reserves for platform rejection of supplied context.
5. **Fix the migration discipline**: add `REVOKE ALL ON FUNCTION auth_internal.get_ai_availability() FROM PUBLIC, authenticated, anon;` to match every sibling migration; also wrap `_bootstrap`'s reads in error handling that falls back to a degraded or non-enrolled state rather than a permanent spinner.
6. **Correct the §5.4 mappings**: give `capability_unknown`/`capability_retired` an app-update presentation and `provider_unavailable` a retry affordance, or record the narrowing in the spec as a documented deviation.
7. **Resolve the ownership and consumption smells**: let the host own and dispose the `ContextResolver`; drive the surface from SDK-exposed chunk/terminal streams rather than double-subscribing `connection.events` (or make the SDK broadcast explicitly); source the context key list from capability discovery instead of a hardcoded constant.
8. **Make the spy tests honest and the probes real**: assert `reachabilityPort.callCount == 0` in T8 alongside the network spy; either route a genuine persistence/export port through the surface so T16/T17 spy on a real channel, or replace them with a static assertion (e.g. the E1 guard extended with persistence-call patterns) and document the change in the spec's Test plan.
9. **Decide the host route's status**: either point `AppRoutes.aiFeatureHost` at `AiFeatureHostPage` with production dependency wiring, or amend plan/tasks to record that the route is a deliberate CP3 stub — the current state contradicts T018's completion claim.

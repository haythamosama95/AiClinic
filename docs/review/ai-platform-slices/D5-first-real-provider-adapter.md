# Slice Review Report — D5: First Real Provider Adapter

**Spec:** `specs/032-first-real-provider-adapter/spec.md` · **Branch:** `ai/032-d5-first-real-provider-adapter` · **Canonical:** §4.3.8 (with §5.3, §13.4; D2 contract `specs/029-provider-port-routing/contracts/provider-port.md`)

## Executive Summary

D5 delivers the artifacts its contract names — `src/provider/deepseek.ts` (`DeepSeekAdapter` behind the D2 `ProviderPort`: injectable transport, secret-store, logger, and journal sinks; canonical→wire mapping; SSE parsing; usage extraction; HTTP-status error classification), the eleven named tests, and a full fixture tree (request-mapping golden, stream, usage, four error classes, malformed, truncated, timeout harness). The happy paths are structurally faithful to the frozen shape: the wire golden matches, error classes map into the taxonomy with D2 retryability derived through `setRetryabilityFromClassification`, and credentials are read per-invoke from the injected secret store. The substantive failures cluster in three places. First, the async path is dead on arrival: because the D2 port is synchronous, the adapter forces promise-returning transports through `waitForPromiseOutcome`, a busy-wait whose microtask callbacks cannot run during the spin — so every real (async) fetch burns the full timeout in a CPU spin and returns a classified `timeout` error regardless of what the provider answered; on the Workers runtime, where `Date.now()` does not advance during synchronous execution, the same loop risks running to the CPU limit. Second, failure containment has two holes in opposite directions: network-level failures (sync throw or promise rejection from the transport) escape `invoke()` as unclassified throws — the exact contract violation the slice exists to prevent — while wire-level failures inside a stream (truncated SSE, mid-stream error events, malformed SSE lines) are silently normalized to *success* with partial content. Third, the stream surface is a post-hoc fiction: the transport is fully buffered, normalized chunks are smuggled out on an extended outcome type the frozen port does not declare, and the terminal chunk is a `text_delta` carrying the entire assembled text a second time. The timeout test passes precisely because of the busy-wait defect, and the credential spy tests — the slice's security done-when — are materially weaker than their names claim.

## Critical Issues

1. **`waitForPromiseOutcome` can never observe a settled promise — every async (i.e. every real) invoke returns `timeout` after burning the full deadline in a CPU spin** (`ai-platform/src/provider/deepseek.ts:334-364`; call site `:432`). The function registers `.then` callbacks and then spins `while (!settled && Date.now() < deadline) {}`. Promise continuation callbacks are microtasks; microtasks cannot run until synchronous execution yields, and the spin never yields — so `settled` is still `false` when the loop exits, the function returns `undefined`, and `invoke` emits the timeout outcome (`:435-437`) for *any* promise-returning transport, including one that resolves immediately with a perfect response. The entire non-fixture path — production `fetch` against `api.deepseek.com` — is therefore unconditionally classified as a provider timeout. On the Cloudflare Workers runtime the failure is worse: `Date.now()` does not advance during synchronous execution within an invocation (timing side-channel mitigation), so the loop's exit condition may never become true and the request burns CPU until the isolate limit kills it — an unclassified worker-exceeded error, not even the taxonomy `timeout`. T-D5-07 passes *because* of this defect: its never-resolving transport is indistinguishable from an immediately-resolving one under this implementation, so the suite is green on the exact path that is broken (see Weak Tests 1). The same busy-wait has already propagated into the D7 adapter (`ai-platform/src/provider/gemini.ts:375-390`), converting a D5 defect into a frozen-suite-shape defect.

2. **Transport-level failures escape `invoke()` as unclassified throws — the exhaustive-classification contract is violated on the most common real failure path** (`ai-platform/src/provider/deepseek.ts:418` — no `try/catch` around `this.transport.fetch`; `:360-362` — a rejected promise is rethrown from inside `waitForPromiseOutcome`). A synchronous throw from the transport (misconfiguration, URL error) propagates straight out of `invoke`; a rejection — DNS failure, connection reset, TLS error, and the `AbortError` any real fetch raises when aborted — is rethrown across the module boundary as an untyped `unknown`. The frozen contract is explicit: "Unclassified provider failures MUST NOT escape as throws; they normalize through the port into a classified canonical error" (`specs/032-first-real-provider-adapter/contracts/first-real-provider-adapter.md` §3.1), and D2's classification contract calls an unclassified failure "a contract violation" (D2 contract §3). Every network-level failure mode a real egress call actually produces is outside the adapter's classification, and no test drives either path (Weak Tests 6). This is also the D4 interaction the prior review predicted: the first real wiring of an abort-rejecting source appears here, and the adapter neither contains the rejection nor exposes the abort (Deviation 3).

## Bugs

1. **The timeout path never aborts the provider fetch — the `AbortController` is dead code on the path that exists to use it** (`ai-platform/src/provider/deepseek.ts:406`, `:428-433`). The `setTimeout` callback that calls `controller.abort()` is a macrotask; it cannot run during the `waitForPromiseOutcome` spin, and `clearTimeout(timeoutTimer)` at `:433` executes immediately after the spin exits — before the timer callback can ever fire. The abort is therefore never delivered: on timeout the adapter stops *waiting* but the outbound connection lives on (in a Worker, the fetch continues in the background and the provider still bills the completion). "Adapters own timeouts / deadline enforcement on the outbound call" (contract §2.1) is implemented as "adapters own stopping waiting." T-D5-07 never asserts the signal fired, so the suite cannot see this (Weak Tests 1).

2. **The terminal stream chunk is a `text_delta` carrying the entire assembled text — content is emitted twice to any consumer that relays deltas** (`ai-platform/src/provider/deepseek.ts:289-294`). After pushing one `text_delta` per provider delta, `normalizeStreamChunks` pushes a terminal chunk of kind `text_delta` whose payload is the full concatenated text. A relaying consumer (D4's broker, per the D2 contract's "D4 relays normalized stream chunks produced at the adapter boundary") that forwards every `text_delta` payload delivers "Hello world" followed by "Hello world" again. The A3 exactly-one-terminal invariant is satisfied in count but violated in semantics: the terminal marker is smuggled on a content-bearing delta instead of being a distinct terminal shape, and `assertExactlyOneTerminal` (`ai-platform/src/contracts/canonical.ts:106-122`) — the guard A3 built for exactly this — is never called by the adapter or the suite.

3. **Truncated and mid-stream-error SSE bodies normalize to `success` with partial content** (`ai-platform/src/provider/deepseek.ts:527-548`). `handleStreamResponse` derives `finishReason` from the last parsed event, defaulting to `"stop"` (`:533`); a stream truncated by a connection drop — no final chunk, no `[DONE]` — yields `kind: "success"` with whatever partial text arrived, indistinguishable from a complete answer. The same hole swallows provider error frames: DeepSeek (like OpenAI) can deliver `data: {"error": …}` mid-stream on a 200 response; `parseSseEvents` parses such frames into `DeepSeekResponse` objects whose `error` field `normalizeStreamChunks` and `handleStreamResponse` never inspect — again `success` with partial content. The truncated-response done-when is proven only against a *complete* JSON body whose `finish_reason` is `"length"` (fixture `truncated/truncated-response.json`; test `ai-platform/test/deepseek-adapter.test.ts:561-590`) — i.e. semantic length-stop mapping, not wire truncation. No fixture exercises a truncated stream (Weak Tests 4).

4. **Malformed SSE lines are silently skipped — stream corruption is reported as success with content loss** (`ai-platform/src/provider/deepseek.ts:242-246`). `parseSseEvents` catches `JSON.parse` failures per line and continues, so a corrupted event mid-stream drops content with no signal; the malformed handling the contract freezes ("malformed recorded body → classified/normalized failure; not an unclassified throw", contract §3) exists only on the non-stream JSON path (`:483-493`). There is no malformed-stream fixture (Weak Tests 5).

5. **`mapFinishReason` collapses every non-`length` finish reason to `"stop"` — provider content-filter and resource-exhaustion finishes are reported as clean completions** (`ai-platform/src/provider/deepseek.ts:172-179`). DeepSeek's documented finish reasons include `content_filter` and `insufficient_system_resource`; a 200 response ending with either maps to `"stop"` and `kind: "success"`. Content filtering is caught only when it arrives as an error *body* (`isContentFiltered`, `:199-210`), so the same provider refusal is terminal `provider_rejected` in one wire shape and silent success in the other. No fixture covers a finish-reason-carried filter (Weak Tests 10).

6. **`isContentFiltered` substring-matches free-text error messages and runs before status classification — retryable failures can be misclassified terminal** (`ai-platform/src/provider/deepseek.ts:199-210`, called first at `:216-218`). Any error body whose message contains "safety" (or "content policy", "content filter") classifies as terminal `provider_rejected` regardless of HTTP status — a 429 or 503 whose provider message happens to mention safety loses its retryability, inverting the D2 classification the suite asserts in T4. Classification by substring over vendor prose is inherently fragile; the status code and structured `type`/`code` fields are the reliable signals.

7. **A missing API key is reported as budget-consuming `provider_rejected` although no provider call was ever made** (`ai-platform/src/provider/deepseek.ts:95-98`, `:389-403`). `consumesBudget` derives the consumed-budget flag from the taxonomy code alone; `provider_rejected` carries `consumesQuota: "Yes"` (`ai-platform/src/errors.ts:107-112`), so a platform misconfiguration (absent secret) that never left the Worker is recorded as having consumed budget — corrupting the usage ledger semantics B4/C3 rely on, and misclassifying an operator-fixable platform fault as a provider rejection.

8. **`timing breakdown` is fabricated as zeros on every result** (`ai-platform/src/provider/deepseek.ts:195`). The canonical result's `timing breakdown` (§5.3) is emitted as `{ queue_ms: 0, provider_ms: 0, total_ms: 0 }` regardless of the actual call — telemetry that flows into journal rows and cost accounting (C2/C3) as real data. The adapter measures nothing; it owns the outbound call and is the only component that could measure `provider_ms`.

9. **Usage extraction silently zero-fills and never requests stream usage from the real provider** (`ai-platform/src/provider/deepseek.ts:162-170`, `:137-144`). `mapUsage` defaults absent fields to `0` — a provider response without a `usage` object reports `{input: 0, output: 0}` (under-counted quota, the §6.5 concern) with no signal — and hardcodes `cached: 0` although DeepSeek's usage object carries `prompt_cache_hit_tokens`. Worse, the wire request never sets `stream_options: { include_usage: true }`, so real DeepSeek streams omit the usage event entirely; the usage chunk path (`:279-287`) is proven against a fixture event (`stream/provider-stream.sse`) the production wire mapping would never elicit. Stream-mode usage extraction is dead in production.

10. **Stream successes emit no log or journal record while non-stream successes do** (`ai-platform/src/provider/deepseek.ts:527-548` vs `:509-518`). `deepseek.invoke_complete` and the journal record are emitted only on the buffered JSON path; the stream path returns silently. Beyond the inconsistency, this means T8's credential spy never exercises a stream invocation — the path with the most provider-controlled content flowing past the sinks is the one with no emission coverage at all.

## Architectural Deviations

1. **The adapter emits journal records with invented event names — encroaching on C3's frozen journal-writer ownership** (`ai-platform/src/provider/deepseek.ts:327-330`, `:398-401`, `:470-475`, `:515-518`). The adapter's `JournalSink` emits `provider.timeout`, `provider.credentials_missing`, `provider.error`, and `provider.invoke_complete` records — event names and shapes defined in no frozen contract. The D5 spec itself states "Journal rows remain C3's concern; this slice only guarantees credential absence from any journalable record it emits" (Constitution Alignment; Out of Scope: "writing `ai_attempt` / R2 envelopes is C3 (§4.3.11)"), and §4.3.8 assigns adapters "no logging policy." The injected-sink design is defensible as diagnostics, but as built the adapter authors a parallel journal vocabulary that C3 never froze and no consumer reads — the same surfaced-but-unjoined hand-off pattern flagged in D1–D4, here on the audit trail.

2. **Normalized stream chunks leave the adapter through an extended outcome type the frozen port does not declare** (`ai-platform/src/provider/deepseek.ts:58-60`; consumed via cast at `ai-platform/test/deepseek-adapter.test.ts:121-123`, `:201-204`). D2 froze `ProviderInvokeResult` as a four-variant discriminated union with no chunk carrier (`ai-platform/src/provider/port.ts:24-28`), even though the D2 contract's prose anticipates "an ordered sequence of `CanonicalStreamChunk` ending with exactly one terminal chunk" on invoke success. D5 resolves the gap by smuggling `streamChunks` onto a module-local extension type that the port's consumers cannot see without casting — the port contract and the port type now disagree, and D5 (which "does not redefine the port" per its Consumes) has de facto extended it. Either the port type needs the chunk carrier (a D2 amendment) or the contract needs to say chunks travel elsewhere.

3. **No caller abort surface: the adapter's `AbortController` is private and unreachable, so §4.3.10's connection-scoped cancellation cannot be wired through this adapter** (`ai-platform/src/provider/deepseek.ts:406`, `:415`). The D2 contract names "abort signal / deadline already on the request" as adapter-local options the port names (D2 contract §2); the frozen port carries neither, and the adapter creates its own controller, passes its signal to the transport, and exposes nothing. §4.3.10's cancellation model — "the in-flight provider fetch is aborted through its abort signal" — has no realization here: D4's broker aborts a signal the adapter never received, and the adapter's own signal fires only from a timeout timer that (per Bug 1) never fires. Combined with Critical 2, a real provider call is uncancellable and its abort-rejection uncontained.

4. **The transport is fully buffered — "stream normalization" is post-hoc batch processing of a complete recording, and incremental delivery is structurally impossible** (`ai-platform/src/provider/deepseek.ts:17-21` — `body: string`; `:479-481`, `:527-529`). `DeepSeekTransportResponse` models the entire SSE body as one in-memory string; the adapter parses it only after the response completes. Nothing streams: no incremental chunk delivery to D4's broker, no backpressure, no mid-stream abort effect, and a slow-streaming provider response occupies the full adapter-owned timeout before a single chunk exists. The known streamless-D2-port context explains the shape, but the consequence belongs in this report: the slice's central "stream normalization" done-when is proven against a processing mode (complete-body replay) that production streaming will never take, so the fixture suite's green says little about the real SSE path.

5. **`deadline` is treated as a relative duration although A3 defines it as "Request deadline in milliseconds" without fixing the epoch** (`ai-platform/src/provider/deepseek.ts:116-126`; A3 contract `specs/017-ai-canonical-inference/contracts/canonical-shapes.md:40`; D1's composer "deadline — from the request (forwarded)"). `resolveTimeoutMs` computes `Math.min(options.timeoutMs, deadline)` as though `deadline` were a remaining-ms budget; if the platform ever stamps an absolute timestamp (the natural reading of "deadline"), every request gets a near-zero or enormous timeout. The fixtures encode the duration reading (`"deadline": 30000`), so the ambiguity is latent, not live — a documentation/contract issue to settle before a second consumer interprets the field differently.

## Missing or Weak Tests

1. **T-D5-07 proves the busy-wait, not deadline enforcement** (`ai-platform/test/deepseek-adapter.test.ts:592-623`). The never-resolving transport is indistinguishable from an immediately-resolving one under `waitForPromiseOutcome` (Critical 1): the test would pass if *every* async invoke returned `timeout` — which is exactly what the implementation does. It never asserts the transport's `signal` fired (Bug 1 makes that assertion impossible), never uses a transport that resolves *within* the deadline to prove the non-timeout async path exists, and burns 50 ms of real wall-clock CPU spinning per run. The named boundary "adapter-owned timeout" has no behavioural proof of enforcement, only of classification of the spin's `undefined` return.

2. **T-D5-03 asserts `expect.any(Number)` against a fixture with concrete values — usage extraction correctness is unproven** (`ai-platform/test/deepseek-adapter.test.ts:480-485`; fixture `usage/provider-response.json` carries 42/18/60). `mapUsage` returning `{input: 0, output: 0}` (Bug 9's missing-usage behaviour) passes this test; the golden comparison the suite shape promises ("Provider usage → canonical usage counters") is never made. The stream-usage half is weaker still: `:487-492` finds the usage chunk and asserts its shape *only if present* — an absent usage chunk passes silently.

3. **T-D5-02 asserts chunk shape only — no content, order, sequence, or terminal-semantics assertion** (`ai-platform/test/deepseek-adapter.test.ts:421-448`). Nothing checks that the deltas equal the fixture's "Hello"/" world", that sequence numbers are ordered and contiguous, that exactly one terminal chunk exists (`assertExactlyOneTerminal` is never called anywhere in the suite), or that the assembled result equals the concatenation of deltas. Bug 2's duplicated terminal `text_delta` is invisible to this test; a normalizer emitting the chunks in reverse order would also pass.

4. **No truncated-stream fixture — T-D5-06 exercises finish-reason mapping on a complete, well-formed body** (`ai-platform/test/deepseek-adapter.test.ts:561-590`; `fixtures/deepseek/truncated/truncated-response.json` is valid, complete JSON). The wire-truncation cases the done-when names — a non-stream body cut mid-JSON (currently → `malformed`, defensible but unasserted) and an SSE stream cut before `[DONE]` (currently → `success` with partial content, Bug 3) — have no cases. The test also accepts `kind === "success"` as a passing outcome for a truncated response (`:581-583`), licensing the exact misclassification Bug 3 describes.

5. **No malformed-stream case** (`ai-platform/test/deepseek-adapter.test.ts:531-559` covers only the non-stream JSON path). A corrupted SSE event mid-stream — the malformed shape a streaming provider actually produces — hits the silent-skip path (Bug 4) with no test to characterize whether skip-and-succeed is the intended port-normalized outcome.

6. **No transport-throw or transport-reject case** (`ai-platform/test/deepseek-adapter.test.ts` — every transport responder returns a response; the only promise transport never settles). Critical 2 is invisible to the suite: one case needs a synchronously throwing transport and one a rejecting promise (DNS/reset/abort), each asserting a classified canonical error rather than an escaped throw. The coverage rule's "every branch of every rule" over the classification contract is unmet without them.

7. **T-D5-08 covers two of five emission paths and never inspects the returned canonical error** (`ai-platform/test/deepseek-adapter.test.ts:625-672`). The spy exercises success and `auth_rejected` only; the timeout, malformed, credentials-missing, and stream paths (the last emits nothing at all — Bug 10) are unchecked. More importantly, the assertion sweeps only the logger/journal sink emissions: the `CanonicalError` returned to the caller carries the provider-native message verbatim (`deepseek.ts:108-111`, `:460-464`) and is precisely the journalable record C3 will persist — a provider that echoes request headers in an error message would leak the credential past every assertion this test makes. The "credentials appear in no log or journal row" done-when is proven over the adapter's own metadata, not over the provider-controlled content the adapter relays into the journal pipeline.

8. **T-D5-11 is near-vacuous — it proves the store was read, not that credentials come from nowhere else** (`ai-platform/test/deepseek-adapter.test.ts:333-369`). The test embeds the known secret in `request_reference`, then asserts only `secretStore.reads` contains the binding. It never inspects the captured wire request, so an adapter that authenticated with the request-embedded secret *and* read the store once would pass; and it attaches no logger or journal even though the success path logs `request_reference` verbatim (`deepseek.ts:509-514`) — meaning the test constructs a credential-in-log channel and then declines to observe it. (That log line is itself a latent leak: any caller placing sensitive material in correlation ids has it emitted at `info` level.)

9. **T-D5-09/T-D5-10 assert export-name regexes — a naming convention, not the prohibition** (`ai-platform/test/deepseek-adapter.test.ts:42-46`, `:228-244`, `:312-331`, `:674-706`). A `shouldRetry()`/`pickFallback()` method or a `logLevel` option matches neither pattern and passes both tests; conversely the tests cannot detect retry *behaviour* at all (e.g. the adapter internally re-issuing the fetch). The stronger form used elsewhere in the program — asserting the dependency/options surface carries no retry/fallback/logging-policy capability — is available here too: `DeepSeekAdapterOptions` could be asserted to accept no retry count, no fallback chain, and no log-level configuration.

10. **No cases for the classification gaps the implementation actually contains**: a 200 response with `finish_reason: "content_filter"` or `"insufficient_system_resource"` (currently `success`/"stop" — Bug 5); a non-2xx response whose message mentions "safety" with a retryable status (currently terminal — Bug 6); a 2xx response with no `usage` object (currently zero-filled — Bug 9); and the missing-credential path's consumed-budget flag (currently `true` — Bug 7). Each is a branch of a rule the coverage rule names; each currently passes silently.

11. **No abort-propagation case** — there is no test (and no port surface, Deviation 3) asserting that a caller-initiated abort reaches the in-flight transport, so the §4.3.10 cancellation chain through a real adapter is unproven end to end.

## Recommended Improvements

- **Make the port asynchronous, or make the adapter honest about synchrony** (Critical 1): the durable fix is the D2 port repair already flagged in prior reviews — `invoke` returning a promise — after which the timeout becomes `Promise.race` against an abort timer and the busy-wait is deleted. Until then, remove `waitForPromiseOutcome` and reject promise-returning transports explicitly, so the fixture suite's transport contract (sync responses) is stated rather than silently universal. Propagate the same fix to the D7 copy.
- **Contain every transport failure at the invoke boundary** (Critical 2): wrap the fetch and the await in `try/catch`; map rejections to a classified canonical error (network/abort failures → `internal_error` retryable, or `cancelled` when the abort came from a caller signal once Deviation 3 is fixed), and add the throwing/rejecting transport cases from Weak Tests 6.
- **Make timeout enforcement real** (Bug 1, Weak Tests 1): on deadline, actually abort the controller and assert in T-D5-07 that the transport's `signal.aborted` became true; add a resolves-within-deadline case proving the non-timeout async path.
- **Fix the stream chunk semantics** (Bugs 2–4): emit the terminal marker on a non-content chunk (or a `text_delta` with empty payload), never re-emit assembled text; treat a stream ending without `[DONE]`/`finish_reason` as a classified truncated outcome rather than `success`; classify mid-stream `error` frames; decide and test the malformed-SSE-line policy (skip-and-succeed needs a `provider_note` or a classified failure — not silence). Call `assertExactlyOneTerminal` in T-D5-02 and assert content, order, and assembly.
- **Classify by structured signals, not prose** (Bugs 5–6): map `finish_reason` values (`content_filter` → `provider_rejected` terminal; `insufficient_system_resource` → retryable) before defaulting to `"stop"`; drive `isContentFiltered` off the structured `type`/`code` fields and let HTTP status win over message substrings.
- **Stop fabricating telemetry and usage** (Bugs 7–9): measure `provider_ms` around the transport call; distinguish "usage absent" from "usage zero" (a missing usage object on a billed response deserves a `provider_note` or a conservative estimate policy, not silent zeros); set `stream_options.include_usage` on streaming wire requests and map DeepSeek's cache-hit tokens into `cached`; set the consumed-budget flag from whether the provider was actually reached, not from the taxonomy code alone.
- **Settle the port's stream and abort surface** (Deviations 2–3): amend the D2 port type to carry the chunk sequence and an abort signal (the D2 contract's prose already names both), rather than extending the outcome module-locally; until then, document in the D5 contract that chunks travel on an extended outcome and cancellation is unwired.
- **Move journal vocabulary to C3 or freeze it** (Deviation 1): either drop the adapter's `JournalSink` (diagnostics via the logger only) or have the emitted event names/shapes frozen in the C3 contract so the audit trail has one author.
- **Strengthen the credential and prohibition spies** (Weak Tests 7–9): sweep the returned `CanonicalError` payloads (provider-native message included) for credential material, not just sink emissions; exercise all five emission paths including stream; in T-D5-11 assert the captured `Authorization` header carries the store secret and not the request-embedded one, with logger/journal attached; replace the export-name regexes with options-surface assertions.
- **Resolve the `deadline` ambiguity in the A3 contract** (Deviation 5): state whether the field is remaining-ms or an absolute timestamp, and align `resolveTimeoutMs` (and D7's copy) with the ruling.

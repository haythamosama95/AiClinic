# Slice Review Report — A6: Protocol Adapter and SSE Framing

**Spec:** `specs/020-ai-protocol-adapter-sse/spec.md` · **Branch:** `ai/020-a6-protocol-adapter-sse` · **Canonical:** §4.3.1, §5.5

## Executive Summary

A6 delivers the §4.3.1 protocol adapter in one module (`ai-platform/src/adapter.ts`): the ingress body-size gate ordered before header parsing and reference generation, the three frozen headers (`x-idempotency-key`, `x-trace-id`, `x-capability-version`), the SSE event vocabulary with `accepted` first, and a sink-level `terminalEmitted` guard that correctly enforces the one-terminal-event invariant against duplicate completion/failure/abort attempts. The happy paths are well tested against the in-process stub. The serious problems sit exactly where the tests do not look: the real connection-scoped cancellation path (`cancel()` and the `request.signal` abort listener) enqueues a `cancelled` event into an already-dead socket — violating the frozen contract ("cancelled carries nothing on the live socket") and throwing at runtime on every client disconnect. The body-size gate measures UTF-16 code units, not bytes, and buffers the entire body before rejecting; a malformed body is never rejected at all. The stub event source, including a test-only `attemptDuplicateTerminal` method, ships in the production module, and the wired live route (`worker.ts:82`) opens streams that never heartbeat and never terminate under the default no-op stub.

## Critical Issues

1. **Connection-scoped cancellation writes to a dead socket and throws** (`adapter.ts:363-377`, `adapter.ts:383-401`). Both the `ReadableStream` `cancel()` callback and the `request.signal` abort listener call `streamController.enqueue(...)` after the client has disconnected. Per the WHATWG Streams spec, `enqueue` on a cancelled/closed controller throws `TypeError`, so every real client disconnect produces an exception (unhandled rejection in the `cancel()` callback; uncaught throw inside the abort event listener). Independent of the throw, this violates the frozen contract `contracts/sse-framing.md` §4 and §5.5 rule 5: `cancelled` "carries nothing on the live socket — a cancellation happens by the client closing the stream, so there is nobody left to receive a response." The correct behaviour is to set `terminalEmitted = true` (preserving the invariant against later sink pushes) without enqueueing. The only tested cancellation path is the stub's `abort()` pushing into a still-live socket (`adapter.test.ts:519-542`), so the bug is invisible to the suite. This is the path §5.5 rule 5 names as *the* cancellation mechanism for the platform.

## Bugs

1. **Body-size gate counts UTF-16 code units, not bytes** (`adapter.ts:308`, limit declared as bytes at `adapter.ts:11`). `bodyText.length` under-counts any non-ASCII body: Arabic and other BMP text is 2–3 bytes per code unit in UTF-8, so a body up to roughly 2–3× the 1 MiB byte limit passes the gate. The stage-1 transport gate is systematically under-enforced for exactly the multilingual payloads a clinic app carries.
2. **The entire body is buffered before the size check** (`adapter.ts:303-310`). `request.text()` reads the full body into isolate memory before the limit is evaluated, and no `Content-Length` pre-check exists. The "reject before any other work" gate rejects only after the most expensive work (buffering an unbounded body) has already happened — a resilience/DoS weakness at the ingress boundary the gate exists to protect.
3. **A malformed body is never rejected** (`adapter.ts:301-315`). The adapter reads the body as text and never parses or shape-checks it; a request with body `"not json"` sails through the gate and opens a stream. Spec FR-004 and the edge case "A malformed request never reaches the taxonomy" require the adapter's own parsing to reject a malformed body. Only the header half of FR-004 is implemented (and only the header half is tested).
4. **Already-aborted request signal leaves the stream open with no terminal event** (`adapter.ts:380-382`). The `if (request.signal.aborted)` branch is an empty block with a comment; when the signal is already aborted at handler entry, no abort listener is registered and nothing marks the stream terminal — the request falls through to the live-route hang (below) with even the disconnect listener missing.

## Architectural Deviations

1. **The wired live route produces streams that never heartbeat and never terminate** (`worker.ts:82` + `adapter.ts:282-295`). The production `POST /v1/requests` path calls `handleAdapterRequest(request)` with no event source, falling to `defaultStubEventSource`, a no-op controller. The stream emits `accepted` and then hangs until the client disconnects (which then hits Critical Issue 1). FR-009 heartbeats and the FR-010 one-terminal-event guarantee hold only under the injected stub; the framing itself owns no heartbeat mechanism (the real `heartbeatTicker` lives in D4's broker, `src/stream/index.ts:197-203`). A6's done-when ("emits heartbeats … ends with exactly one terminal event") is stub-satisfied only, and the deployed route leaks hanging connections until D4 lands.
2. **The adapter invents a ULID-only constraint on client-supplied trace ids** (`adapter.ts:13`, `adapter.ts:269-271`). A2's `resolveTraceId` accepts any non-empty supplied id (`trace.ts:23-28`), and neither §13.1 nor the frozen contract restricts the client trace id to ULID format — the ULID is the *gateway-generated fallback when absent*. The adapter rejects any non-ULID client trace id (e.g. a UUID) with a parse failure, adding validation the architecture does not name and narrowing A2's consumed contract.
3. **Test scaffolding ships in the production module** (`adapter.ts:44-56`, `adapter.ts:148-215`, `adapter.ts:282-295`). `StubEventSourceController`, `createModeGatedStubEventSource`, and `defaultStubEventSource` — including `attemptDuplicateTerminal`, a method that exists solely to probe the one-terminal-event guard — are exported from `src/adapter.ts`. Clarification Q2 scoped the stub to the test harness; the test file defines its own equivalent (`adapter.test.ts:185-243`), so the `src/` copy is redundant as well as misplaced. Test concerns compiled into the deployed Worker bundle.
4. **The 413 error body carries empty `request_reference` and `trace_id`** (`adapter.ts:225-236`). This follows acceptance scenario 1 ("no reference is generated") but sits in tension with FR-006 ("every error response … MUST carry the request reference, the trace id") and A2's error-body contract; the fields are present but meaningless. Spec-internal ambiguity the implementation resolves silently — worth a contract note, since the trace id could be parsed from headers at negligible cost without violating "no header is handled" (parsing ≠ handling, but the spec does not say so).
5. **Adapter-local parse failures use a bare 422** (`adapter.ts:238-244`). §5.4 prohibits a taxonomy code mapping to a bare 400; the choice of bare 422 is compliant but collides numerically with four taxonomy codes that map to 422 (`context_required`, `context_invalid`, `validation_failed`, `provider_rejected`, `errors.ts:65-118`). Clients branch on the taxonomy code, not the status, so this is safe — but it is a needless ambiguity the contract does not document.

## Missing or Weak Tests

1. **No test exercises the real disconnect path.** T10 (`adapter.test.ts:519-542`) drives cancellation via the stub's `abort()` into a live socket; the `cancel()` callback (`adapter.ts:363-377`) and the `request.signal` abort listener (`adapter.ts:383-401`) are never executed by any test. The required case "abort mid-stream still yields exactly one terminal event" is covered only for the simulated path — the real one is both untested and broken (Critical Issue 1). No test performs `reader.cancel()` or aborts a request signal mid-stream.
2. **No malformed-body test.** T5 (`adapter.test.ts:354-393`) covers only malformed/missing headers; the FR-004 requirement that a malformed *body* is rejected by the adapter's own parsing has no test — and would fail, since the behaviour is unimplemented (Bug 3).
3. **Malformed-header coverage is one-sided** (`adapter.test.ts:355-371`). Tested: missing idempotency key, missing version pin, garbage trace id. Untested branches (`adapter.ts:255-271`): empty/whitespace `x-idempotency-key`, empty/whitespace `x-capability-version`, and present-but-empty `x-trace-id` (three distinct rejection branches); also no "malformed" case for the idempotency key or version pin at all, and no documented definition of what malformed means for either.
4. **T1 does not prove "before any other work" beyond the reference spy** (`adapter.test.ts:274-293`). It asserts `generateRequestReference` is not called and no SSE stream opens, but not that headers went unhandled — e.g. an oversized body *with* malformed headers must still yield 413, not a parse-failure 422. The ordering claim of FR-002 is only partially pinned.
5. **Heartbeat coverage is stub-illusion.** T7 (`adapter.test.ts:433-453`) proves only that a heartbeat pushed by the stub is framed and is neither content nor terminal. Nothing asserts the framing emits heartbeats autonomously while idle (FR-009) — no such mechanism exists in the adapter (Deviation 1) — and the "heartbeat does not satisfy the one-terminal-event invariant" half of the edge case is only implicit in the T8 terminal count.
6. **No test asserts the no-per-request-state edge case directly.** The spec edge case requires "closing the stream cancels the request with no state object created"; coverage is indirect (the closure-local `terminalEmitted` flag at `adapter.ts:328` is connection-scoped, which satisfies §4.4/§9.7 in review, but no test pins it).

## Recommended Improvements

- **Fix the disconnect path first** (`adapter.ts:363-401`): in both `cancel()` and the abort listener, set `terminalEmitted = true` and return without enqueueing; contract §4 forbids writing `cancelled` to the dead socket. Add a test that cancels the reader mid-stream and asserts no throw and no second terminal event.
- **Make the size gate byte-accurate and early**: reject on `Content-Length` when present, otherwise read the body via a reader accumulating `Uint8Array` byte counts and abort at the first chunk that crosses the limit — never buffer past the cap (`adapter.ts:301-310`).
- **Parse the body at stage 1** (JSON parse, minimal shape check) so a malformed body is rejected per FR-004 before any stream opens (`adapter.ts:301-315`); add the corresponding test.
- **Move all stub machinery out of `src/adapter.ts`** into `test/` (or a test-only module); delete `attemptDuplicateTerminal`, `createModeGatedStubEventSource`, and `defaultStubEventSource` from the shipped module — the test file already owns an equivalent (`adapter.test.ts:185-243`).
- **Resolve the trace-id acceptance rule in the contract**: either accept any non-empty client trace id (A2's contract, `trace.ts:23-28`) or freeze the ULID requirement in `contracts/sse-framing.md` §1 — do not leave it as an undocumented adapter invention (`adapter.ts:269`).
- **Decide the live-route story before D4**: either gate `POST /v1/requests` behind the not-yet-wired broker, or have the adapter fail fast when no event source is provided, so the deployed route cannot leak hanging, heartbeat-less, never-terminating streams (`worker.ts:82`, `adapter.ts:282-295`).
- **Handle the already-aborted signal** (`adapter.ts:380-382`) instead of the empty branch — at minimum register the same terminal-marking logic or reject the request outright.

# Slice Review Report — D7: Second Provider Adapter

**Spec:** `specs/034-second-provider-adapter/spec.md` · **Branch:** `ai/034-d7-second-provider-adapter` · **Canonical:** §4.3.8, §13.5 (with §5.3; D2 contracts `specs/029-provider-port-routing/contracts/provider-port.md`, `routing-decision.md`)

## Executive Summary

D7 delivers the artifacts its contract names: `src/provider/gemini.ts` (`GeminiAdapter` behind the D2 `ProviderPort`, duplicating D5's inject pattern), a full fixture tree under `test/fixtures/gemini/` (request-mapping golden, stream, usage, four wire error classes, malformed, truncated, timeout harness), the eleven named adapter tests plus the two policy tests, a versioned routing-policy document registering `gemini` after `deepseek` (`control/routing-policy/platform-default/1.json`), and a thin `provider_id` → adapter map (`src/provider/wiring.ts`). The branch diff is genuinely clean — the merge-base diff touches only the adapter, wiring, policy data, tests, fixtures, and spec documents; `port.ts`, `deepseek.ts`, `router/index.ts`, and every pipeline module are untouched, so the "added by routing-policy edit with no pipeline diff" done-when holds in fact. The deferred eval clause (FR-010 / T12 / SC-005, `blocked_on_F1`) was a legitimate split at authoring time, and F1 has since landed with `gemini-1.5-flash` in its live-smoke targets. The substantive failures are of two kinds. First, the D5 review's defects were copied almost line-for-line into the second adapter and are now frozen into a second module: the `waitForPromiseOutcome` busy-wait that makes every real (async) invoke return `timeout`, unclassified transport throws escaping `invoke()`, the abort timer that can never fire, the duplicated terminal `text_delta`, truncated/mid-stream-error streams normalized to `success`, fabricated zero telemetry, and the budget-consuming missing-credential error all reappear — each is a D7 finding now, because the slice's own contract re-freezes "classification of every failure as retryable or terminal" and "timeouts / deadline enforcement on the outbound call" for this adapter. Second, the D7-specific scope has its own holes: the wire mapping silently drops `toolDeclarations`, the format-directive schema, `top_k`, and `allowedLanguages`, and emits canonical `system`/`data` roles verbatim into a Gemini `contents[].role` field that rejects them; the policy's `model_id` is decorative because the adapter hardcodes the model; the "thin wiring map" the contract freezes is dead code — nothing in production constructs either real adapter, so the registered fallback target is unreachable end-to-end; and T13's "no pipeline diff" proof greps for the string "gemini" rather than proving a diff property. The test suite mirrors D5's weaknesses: the timeout test passes *because* of the busy-wait, usage extraction is asserted with `expect.any(Number)` against a fixture with concrete values, the credential spies never sweep the returned canonical error payload, and no case drives a truncated stream, a malformed stream, or a throwing/rejecting transport.

## Critical Issues

1. **The inherited `waitForPromiseOutcome` busy-wait can never observe a settled promise — every async (i.e. every real) Gemini invoke returns `timeout` after burning the full deadline in a CPU spin** (`ai-platform/src/provider/gemini.ts:355-384`; call site `:448`). This is the D5 Critical 1 mechanism copied verbatim: `.then` callbacks are registered, then `while (!settled && Date.now() < deadline) {}` spins without yielding, so the microtask that would set `settled` can never run, the loop exits on the deadline, and `invoke` emits the timeout outcome (`:452-454`) for *any* promise-returning transport — including one that resolves instantly with a perfect response. The entire production egress path against `generativelanguage.googleapis.com` is therefore unconditionally classified as a provider timeout; on the Workers runtime, where `Date.now()` does not advance during synchronous execution, the same loop risks running to the isolate CPU limit — an unclassified worker-exceeded error, not even the taxonomy `timeout`. D7's own contract re-freezes the duty this breaks: "Timeouts / deadline enforcement on the outbound call" and "Classification of every failure as retryable or terminal" (`specs/034-second-provider-adapter/contracts/second-provider-adapter.md` §2.1), against §4.3.8's "Adapters own … timeouts, and classification of every failure as retryable or terminal". What was a single-adapter defect in D5 is now a *pattern*: the slice that exists to prove provider independence has cloned the first adapter's fatal async path into the second, and T-D7-07 passes precisely because of it (Weak Tests 1). The D5 review explicitly warned this copy existed; it shipped unchanged.

2. **Transport-level failures escape `invoke()` as unclassified throws — the exhaustive-classification contract is violated on the most common real failure path, now in both real adapters** (`ai-platform/src/provider/gemini.ts:438` — no `try/catch` around `this.transport.fetch`; `:380-382` — a rejected promise is rethrown from inside `waitForPromiseOutcome`). A synchronous throw from the transport propagates straight out of `invoke`; a rejection — DNS failure, connection reset, TLS error, and the `AbortError` any real fetch raises when aborted — is rethrown across the module boundary as untyped `unknown`. The D7 contract is explicit: "Unclassified provider failures MUST NOT escape as throws; they normalize through the port into a classified canonical error" (`contracts/second-provider-adapter.md` §3.1), and acceptance scenario 5 generalizes it: a recorded failure must produce "a classified canonical error … and not an unclassified throw" (spec.md, US1 scenario 5). Every network-level failure mode a real Gemini egress call produces sits outside the adapter's classification, and no test drives either path (Weak Tests 6). Because the second provider is the *fallback* target, this hole is worse than in D5: when D3 walks the chain to Gemini after a primary failure, an unclassified Gemini transport throw escapes the attempt loop entirely rather than surfacing as the classified terminal failure the chain walk expects.

## Bugs

1. **The timeout path never aborts the provider fetch — the `AbortController` is dead code on the path that exists to use it** (`ai-platform/src/provider/gemini.ts:426-427`, `:444-450`). The `setTimeout(() => controller.abort(), timeoutMs)` callback is a macrotask; it cannot run during the `waitForPromiseOutcome` spin, and `clearTimeout(timeoutTimer)` at `:450` executes immediately after the spin exits — before the timer callback can ever fire. On timeout the adapter stops *waiting* but the outbound connection lives on; in a Worker the fetch continues in the background and Gemini still bills the completion. "Timeouts / deadline enforcement on the outbound call" (contract §2.1) is implemented as "stopping waiting." T-D7-07 never asserts the signal fired (Weak Tests 1).

2. **The terminal stream chunk is a `text_delta` carrying the entire assembled text — content is emitted twice to any consumer that relays deltas** (`ai-platform/src/provider/gemini.ts:309-314`). After pushing one `text_delta` per provider delta, `normalizeStreamChunks` pushes a terminal chunk of kind `text_delta` whose payload is the full concatenated text. A relaying consumer (D4's broker, per the D2 contract's "D4 relays normalized stream chunks produced at the adapter boundary") that forwards every `text_delta` payload delivers "Hello world" followed by "Hello world" again. The A3 exactly-one-terminal invariant is satisfied in count but violated in semantics, and `assertExactlyOneTerminal` (`ai-platform/src/contracts/canonical.ts:176-186`) is never called by the adapter or the suite.

3. **Truncated and mid-stream-error SSE bodies normalize to `success` with partial content** (`ai-platform/src/provider/gemini.ts:541-564`). `handleStreamResponse` derives `finishReason` from the last parsed event, defaulting to `"STOP"` (`:547`); a stream cut by a connection drop yields `kind: "success"` with whatever partial text arrived, indistinguishable from a complete answer. Mid-stream `data: {"error": …}` frames — which Gemini can deliver on a 200 SSE response — parse into `GeminiResponse` objects whose `error` field (`:91-95`) neither `normalizeStreamChunks` nor `handleStreamResponse` ever inspects: again `success` with partial content. The truncated-response done-when is proven only against a *complete* JSON body whose `finishReason` is `"MAX_TOKENS"` (`fixtures/gemini/truncated/truncated-response.json`; T-D7-06 at `ai-platform/test/gemini-adapter.test.ts:559-587`) — semantic length-stop mapping, not wire truncation. No fixture exercises a truncated stream (Weak Tests 4).

4. **Malformed SSE lines are silently skipped — stream corruption is reported as success with content loss** (`ai-platform/src/provider/gemini.ts:251-269`, the `catch { // skip malformed SSE lines }` at `:263-265`). A corrupted event mid-stream drops content with no signal; the malformed handling the contract freezes ("Malformed recorded body → classified/normalized failure; not an unclassified throw", contract §3) exists only on the buffered JSON path (`:500-510`). There is no malformed-stream fixture (Weak Tests 5).

5. **The stream path never checks content filtering, and `mapFinishReason` collapses every non-`MAX_TOKENS` finish reason to `"stop"` — provider safety blocks and recitation refusals stream out as clean completions** (`ai-platform/src/provider/gemini.ts:196-202`, `:541-564`). `isContentFiltered` (`:224-231`) is called only on the buffered JSON path (`:511`) and inside `classifyHttpFailure` (`:237-239`) — never on the stream path, so a Gemini stream whose terminal event carries `finishReason: "SAFETY"` returns `kind: "success"`, `finishReason: "stop"`. On the buffered path, `RECITATION`, `OTHER`, and `SPII` finishes likewise fall through `isContentFiltered` (which matches only `SAFETY`/`BLOCKLIST`) and map to `"stop"`/`success`. The same provider refusal is terminal `provider_rejected` in one wire shape and silent success in the other — and the contract's own T4 table names "Provider safety / block (`blockReason` / SAFETY)" as the `content_filtered` class's typical signal (`contracts/second-provider-adapter.md` §3.1), a signal the stream shape carries and the adapter ignores.

6. **A missing API key is reported as budget-consuming `provider_rejected` although no provider call was ever made** (`ai-platform/src/provider/gemini.ts:408-413`, `:100-103`). `consumesBudget` derives the flag from the taxonomy code alone; `provider_rejected` carries `consumesQuota: "Yes"` (`ai-platform/src/errors.ts:107-112`), so a platform misconfiguration (absent `GEMINI_API_KEY` secret) that never left the Worker is recorded as having consumed budget — corrupting the usage-ledger semantics B4/C3 rely on, and misclassifying an operator-fixable platform fault as a provider rejection.

7. **Telemetry is fabricated: `timing` is zeros on every result and `providerRequestId` is the hardcoded constant `"gemini-unknown"`** (`ai-platform/src/provider/gemini.ts:218-219`). The canonical result's `timing breakdown` (§5.3) flows into journal rows and cost accounting (C2/C3) as real data; the adapter measures nothing although it owns the outbound call and is the only component that could measure `provider_ms`. The invented request-id constant is worse than a zero: every Gemini result carries the same fake identifier, so any support or audit join on `providerRequestId` silently collapses all Gemini traffic into one record.

8. **Usage extraction silently zero-fills and drops Gemini's cache counter** (`ai-platform/src/provider/gemini.ts:186-194`, `:76-81`). `mapUsage` defaults absent fields to `0` — a response without `usageMetadata` reports `{input: 0, output: 0}` (under-counted quota) with no signal — and hardcodes `cached: 0` although Gemini's usage object carries `cachedContentTokenCount`; the `GeminiUsage` type doesn't even declare the field, so cache-hit tokens are discarded at the type level. (Unlike DeepSeek, Gemini streams include `usageMetadata` by default, so the stream-usage path is not dead here — the zero-fill and dropped cache counter are.)

9. **Stream successes emit no log or journal record while buffered successes do** (`ai-platform/src/provider/gemini.ts:541-564` vs `:525-533`). `gemini.invoke_complete` and the journal record are emitted only on the buffered path; the stream path returns silently. Beyond the inconsistency, T-D7-08's credential spy never exercises a stream invocation — the path with the most provider-controlled content flowing past the sinks is the one with no emission coverage at all.

10. **The wire mapping silently drops canonical fields and emits roles Gemini rejects** (`ai-platform/src/provider/gemini.ts:140-178`, `:134-138`). Four distinct losses: (a) `toolDeclarations` — a manifest field of `CanonicalRequest` (`ai-platform/src/contracts/canonical.ts:87`) — is never read; a canonical request carrying tools produces an identical wire request to one without. (b) `formatDirective.schema` / `outputSchemaRef` are ignored: only `type === "json"` maps to `responseMimeType: "application/json"` (`:165-167`), so a JSON-with-schema directive loses the schema although Gemini supports `responseSchema` — the "provider-specific structured-output wire mechanics" the contract assigns this adapter (§2.1) are half-implemented, and D6's structured modes will inherit the gap. (c) `samplingConstraints.top_k` and `allowedLanguages` (`canonical.ts:69-73`) are dropped; Gemini's `generationConfig` supports `topK`. (d) `mapRoleToGemini` maps only `assistant` → `model` and passes everything else through verbatim — canonical roles include `system` and `data` (`canonical.ts:47-51`), which Gemini's `contents[].role` rejects (system instruction travels in a separate `systemInstruction` field), and each canonical part becomes its own `contents` entry, so two consecutive same-role parts violate Gemini's user/model alternation requirement. Every fixture uses a single `user` part, so all four losses are invisible to the suite (Weak Tests 12).

## Architectural Deviations

1. **The adapter emits journal records with invented event names — encroaching on C3's frozen journal-writer ownership, now from a second module** (`ai-platform/src/provider/gemini.ts:347-351`, `:418-421`, `:487-492`, `:530-533`). The `JournalSink` emits `provider.timeout`, `provider.credentials_missing`, `provider.error`, and `provider.invoke_complete` — event names and shapes defined in no frozen contract. The D7 spec itself states "Journal rows remain C3's concern; this slice only guarantees credential absence from any journalable record it emits" (Constitution Alignment; Out of Scope: "writing `ai_attempt` / R2 envelopes is C3 (§4.3.11)"), and §4.3.8 assigns adapters "no logging policy." D5's parallel journal vocabulary has been duplicated rather than settled: two real adapters now author audit-trail records that C3 never froze and no consumer reads.

2. **Normalized stream chunks leave the adapter through an extended outcome type the frozen port does not declare** (`ai-platform/src/provider/gemini.ts:59-61`; consumed via cast at `ai-platform/test/gemini-adapter.test.ts:201-205`). D2 froze `ProviderInvokeResult` as a four-variant discriminated union with no chunk carrier (`ai-platform/src/provider/port.ts:24-28`). D7 repeats D5's resolution — smuggling `streamChunks` onto a module-local extension type the port's consumers cannot see without casting — so the port contract and the port type now disagree in *two* adapter modules, and the divergence is entrenched as the established pattern any third adapter will copy.

3. **No caller abort surface: the adapter's `AbortController` is private and unreachable, so §4.3.10's connection-scoped cancellation cannot be wired through this adapter** (`ai-platform/src/provider/gemini.ts:426-427`). The frozen port carries no signal; the adapter creates its own controller, passes its signal to the transport, and exposes nothing. D4's broker aborts a signal the adapter never received, and the adapter's own signal fires only from a timeout timer that (per Bug 1) never fires. Combined with Critical 2, a real Gemini call is uncancellable and its abort-rejection uncontained — the exact failure containment a fallback target most needs, since it is invoked precisely when the primary path is already degraded.

4. **The transport is fully buffered — "stream normalization" is post-hoc batch processing of a complete recording, and incremental delivery is structurally impossible** (`ai-platform/src/provider/gemini.ts:18-22` — `body: string`; `:496-498`, `:541-543`). `GeminiTransportResponse` models the entire SSE body as one in-memory string, parsed only after the response completes: no incremental chunk delivery to D4's broker, no backpressure, no mid-stream abort effect, and a slow-streaming Gemini response occupies the full adapter-owned timeout before a single chunk exists. The slice's central "stream normalization" done-when is proven against a processing mode (complete-body replay) that production streaming will never take.

5. **`deadline` is treated as a relative duration although A3 defines it as "Request deadline in milliseconds" without fixing the epoch** (`ai-platform/src/provider/gemini.ts:121-131`; A3 contract `specs/017-ai-canonical-inference/contracts/canonical-shapes.md:40`). `resolveTimeoutMs` computes `Math.min(options.timeoutMs, deadline)` as though `deadline` were a remaining-ms budget; if the platform ever stamps an absolute timestamp, every request gets a near-zero or enormous timeout. The ambiguity D5 flagged remains unresolved, and a second consumer has now encoded the duration reading (`fixtures/gemini/timeout/harness.json` plus `"deadline": 30000` fixtures) — two adapters must now be changed together when the ruling lands.

6. **The wiring map the contract freezes is dead code, and the policy's `model_id` is decorative — the registered fallback target is unreachable and its model half is unhonoured** (`ai-platform/src/provider/wiring.ts:6-24`; `ai-platform/src/invocation/index.ts:49`, `:185`). Nothing imports `wiring.ts`: D3's invocation resolves ports through an injected `portResolver(providerId)` that no production module supplies — no code anywhere in `src/` constructs `GeminiAdapter` (or `DeepSeekAdapter`) outside tests. The contract freezes `wiring.ts` as "Thin `provider_id` → adapter construction map" (§5.2), and the slice delivered exactly that — a map nothing consults — repeating the surfaced-but-unjoined hand-off pattern flagged in D1–D5, here on the slice's headline claim. Compounding it, the adapter hardcodes `gemini-1.5-flash` (`ai-platform/src/provider/gemini.ts:13`, `:180-184`) while the routing target carries `model_id: "gemini-1.5-flash"` (`control/routing-policy/platform-default/1.json:32-45`): the port forwards no model identity, so a policy edit repointing the Gemini target at a different model — the kind of change "routing policy alone" is supposed to suffice for — would silently change nothing. The "registered as a low-priority fallback target by routing policy alone" done-when holds at the router-data layer (T-D7-14 proves ordering) but terminates there.

## Missing or Weak Tests

1. **T-D7-07 proves the busy-wait, not deadline enforcement** (`ai-platform/test/gemini-adapter.test.ts:590-621`). The never-resolving transport is indistinguishable from an immediately-resolving one under `waitForPromiseOutcome` (Critical 1): the test would pass if *every* async invoke returned `timeout` — which is exactly what the implementation does. It never asserts the transport's `signal.aborted` became true (Bug 1 makes that assertion impossible), never uses a transport that resolves *within* the deadline to prove the non-timeout async path exists, and burns 50 ms of real wall-clock CPU spinning per run. The named boundary "adapter-owned timeout" has no behavioural proof of enforcement, only of classification of the spin's `undefined` return.

2. **T-D7-03 asserts `expect.any(Number)` against a fixture with concrete values — and its stream half is vacuous by construction** (`ai-platform/test/gemini-adapter.test.ts:479-490`; fixture `usage/provider-response.json` carries 42/18/60). `mapUsage` returning `{input: 0, output: 0}` (Bug 8's missing-usage behaviour) passes. The stream-usage half is worse: the usage canonical request has `"stream": false` (`fixtures/gemini/usage/canonical-request.json:10`), so the outcome carries no `streamChunks`, `getStreamChunks(outcome)` returns `[]`, and the `if (usageChunk)` guard at `:486-490` can never execute — an assertion block that is dead code in a passing test.

3. **T-D7-02 asserts chunk shape only — no content, order, sequence, or terminal-semantics assertion** (`ai-platform/test/gemini-adapter.test.ts:419-446`). Nothing checks that the deltas equal the fixture's "Hello"/" world", that sequence numbers are ordered and contiguous, that exactly one terminal chunk exists (`assertExactlyOneTerminal` is never called anywhere in the suite), or that the assembled result equals the concatenation of deltas. Bug 2's duplicated terminal `text_delta` is invisible to this test.

4. **No truncated-stream fixture — T-D7-06 exercises finish-reason mapping on a complete, well-formed body** (`ai-platform/test/gemini-adapter.test.ts:559-587`; `fixtures/gemini/truncated/truncated-response.json` is valid, complete JSON). The wire-truncation cases the done-when names — a non-stream body cut mid-JSON (currently → `malformed`, defensible but unasserted) and an SSE stream cut mid-flight (currently → `success` with partial content, Bug 3) — have no cases. The test also accepts `kind === "success"` as a passing outcome for a truncated response (`:579-582`), licensing the exact misclassification Bug 3 describes.

5. **No malformed-stream case** (`ai-platform/test/gemini-adapter.test.ts:529-557` covers only the buffered JSON path). A corrupted SSE event mid-stream — the malformed shape a streaming provider actually produces — hits the silent-skip path (Bug 4) with no test to characterize whether skip-and-succeed is the intended port-normalized outcome.

6. **No transport-throw or transport-reject case** (every transport responder in `ai-platform/test/gemini-adapter.test.ts` returns a response; the only promise transport never settles). Critical 2 is invisible to the suite: one case needs a synchronously throwing transport and one a rejecting promise (DNS/reset/abort), each asserting a classified canonical error rather than an escaped throw. The coverage rule's "every branch of every rule" over the classification contract is unmet without them — and this is the fallback provider, where containment matters most.

7. **T-D7-08 covers two of five emission paths and never inspects the returned canonical error** (`ai-platform/test/gemini-adapter.test.ts:623-674`). The spy exercises buffered success and `auth_rejected` only; the timeout, malformed, credentials-missing, and stream paths (the last emits nothing at all — Bug 9) are unchecked. More importantly, the sweep at `:668-673` covers only logger/journal sink emissions: the `CanonicalError` returned to the caller carries the provider-native message verbatim (`gemini.ts:478-481`) and is precisely the journalable record C3 will persist — a provider error body that echoes the `x-goog-api-key` header value would leak the credential past every assertion this test makes. The "credentials appear in no log or journal row" done-when is proven over the adapter's own metadata, not over the provider-controlled content the adapter relays.

8. **T-D7-11 is near-vacuous — the same secret value on both channels cannot distinguish them, and the leak channel it constructs is never observed** (`ai-platform/test/gemini-adapter.test.ts:333-368`). The test sets `request_reference` to `KNOWN_SECRET` — the *same* value the store returns — so even a captured-wire assertion could not tell which source authenticated; and it asserts only `secretStore.reads` contains the binding (`:365-366`), never inspecting the captured request. Worse, it attaches no logger although the success path logs `request_reference` verbatim (`gemini.ts:525-529`) — the test embeds the secret in a field the adapter emits at `info` level, then declines to attach the sink that would reveal it. (That log line is itself a latent leak, inherited from D5: any caller placing sensitive material in correlation ids has it emitted at `info` level.)

9. **T-D7-09/T-D7-10 assert export-name regexes — a naming convention, not the prohibition** (`ai-platform/test/gemini-adapter.test.ts:42-47`, `:230-245`, `:311-331`, `:676-712`). A `shouldRetry()`/`pickFallback()` method or a `logLevel` option matches neither pattern and passes both tests; the tests cannot detect retry *behaviour* at all (e.g. the adapter internally re-issuing the fetch). The stronger form — asserting `GeminiAdapterOptions` accepts no retry count, no fallback chain, and no log-level configuration — is available and unused.

10. **T-D7-13 greps for the string "gemini" — it does not prove the no-pipeline-diff done-when it names** (`ai-platform/test/second-provider-policy.test.ts:136-167`). The test checks that the allowlisted paths exist, that `wiring.ts` doesn't import four pipeline modules, and that those modules don't contain the substring "gemini"/"Gemini". A pipeline change that accommodates the second provider without naming it — a port-type edit, an invocation change keyed on chain length, a validator tweak — passes every assertion. The done-when is a diff property; the test is a string property. (The git history shows the diff was in fact clean — adapter, wiring, policy data, tests, fixtures, docs only — so the done-when *holds*; it is simply not what the test proves. A test that diffs the slice's merge-base file set against the allowlist would prove it.)

11. **T-D7-14 proves router ordering but the honoured fallback can never fire end-to-end** (`ai-platform/test/second-provider-policy.test.ts:169-197`). The assertions on chain order, recorded `rule_id`, and determinism are faithful to the D2 selection-reason contract. But no test — here or anywhere — resolves `gemini` through D3's `portResolver` into a constructed adapter and walks to it after a primary failure (Deviation 6: nothing can), so "fallback ordering honoured" is proven only up to the router's output boundary. The single-rule policy document also means the ordering proof rests on one catch-all rule; no case exercises Gemini's exclusion or demotion under a more specific rule.

12. **No cases for the classification and mapping gaps the implementation actually contains**: a stream whose terminal event carries `finishReason: "SAFETY"` (currently `success` — Bug 5); a `promptFeedback.blockReason` body — the signal the contract's own T4 table names first for `content_filtered` (contract §3.1), handled by `isContentFiltered` (`gemini.ts:225-227`) with no fixture exercising it; a generic non-2xx such as 400/404 (the `provider_rejected` default branch at `gemini.ts:248` — an entire branch of the classification rule with no case); a buffered `RECITATION` finish; a 200 response with no `usageMetadata` (currently zero-filled — Bug 8); the missing-credential path's consumed-budget flag (currently `true` — Bug 6); a multi-part request, a `system`-role part, a JSON-with-schema directive, and a tool-carrying request (all silently mis-mapped — Bug 10); and an abort-propagation case (no port surface exists — Deviation 3). Each is a branch of a rule or an inherited invariant the §3.10 coverage rule names; each currently passes silently.

## Recommended Improvements

- **Repair the async path once, in both adapters, at the port** (Critical 1): the durable fix remains the D2 port repair — `invoke` returning a promise — after which the timeout becomes `Promise.race` against an abort timer and `waitForPromiseOutcome` is deleted from `gemini.ts` and `deepseek.ts` together. Until then, reject promise-returning transports explicitly so the fixture suite's sync-transport contract is stated rather than silently universal. Do not let a third adapter copy this pattern again.
- **Contain every transport failure at the invoke boundary** (Critical 2): wrap the fetch and the await in `try/catch`; map rejections to a classified canonical error (network/abort failures → retryable `internal_error`, or `cancelled` once Deviation 3 is fixed); add the throwing/rejecting transport cases from Weak Tests 6. Apply to both real adapters.
- **Make timeout enforcement real** (Bug 1, Weak Tests 1): on deadline, actually abort the controller; assert in T-D7-07 that the transport's `signal.aborted` became true; add a resolves-within-deadline case proving the non-timeout async path.
- **Fix the stream semantics** (Bugs 2–5): emit the terminal marker on a non-content chunk (or an empty-payload delta), never re-emit assembled text; treat a stream ending without a terminal `finishReason` as a classified truncated outcome rather than `success`; classify mid-stream `error` frames; run `isContentFiltered` on the stream path's terminal event and map `RECITATION` to `provider_rejected`; decide and test the malformed-SSE-line policy (skip-and-succeed needs a `provider_note` or a classified failure — not silence). Call `assertExactlyOneTerminal` in T-D7-02 and assert content, order, and assembly.
- **Stop fabricating telemetry and usage** (Bugs 6–8): measure `provider_ms` around the transport call; surface the absence of a provider request id explicitly rather than emitting the `"gemini-unknown"` constant; distinguish "usage absent" from "usage zero" (a `provider_note`, not silent zeros); map `cachedContentTokenCount` into `cached`; set the consumed-budget flag from whether the provider was actually reached.
- **Complete the wire mapping or document its floor** (Bug 10): map `toolDeclarations` to Gemini `tools`, `formatDirective.schema` to `responseSchema`, and `top_k` to `topK`; route `system`-role parts to `systemInstruction` and merge consecutive same-role parts — or, if these are deliberately deferred to D6's structured modes, say so in the contract and add fixtures that pin the current drop behaviour so it is a choice, not an accident.
- **Join the wiring map to the invocation path and honour the policy's model identity** (Deviation 6): have D3's production `portResolver` built from `createProviderAdapter` at the Worker boundary (one line of joining code), and thread the chain entry's `model_id` to the adapter — otherwise restate the done-when to acknowledge that registration currently terminates at router output.
- **Move journal vocabulary to C3 or freeze it** (Deviation 1): either drop both adapters' `JournalSink` (diagnostics via the logger only) or have the emitted event names/shapes frozen in the C3 contract so the audit trail has one author.
- **Strengthen the credential and prohibition spies** (Weak Tests 7–9): sweep the returned `CanonicalError` payloads (provider-native message included) for credential material, not just sink emissions; exercise all five emission paths including stream; in T-D7-11 use *different* values for the store secret and the request-embedded decoy, attach logger/journal, and assert the captured `x-goog-api-key` carries the store value; replace the export-name regexes with options-surface assertions.
